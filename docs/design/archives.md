# Archive and export completion

Extends approved screens revision 2 without adding controls to the writing surface.

## Portable recovery archive
Settings > Privacy gains a Backup section with “Export Archive…” and “Import Archive…”. Export includes every local journal, template, deleted entry, conflict and original version, plus all referenced images. It is encrypted with the journal key; the archive includes its encrypted recovery envelope. Copy: “An encrypted copy of your journals, including images and earlier versions. Keep your recovery key separately.” Local unsaved text must flush first; missing images cause a clear failure (“Some images haven’t downloaded. Connect to your server and try again.”), never an apparently complete backup. Use the native save/export picker. No destination preference is remembered without the OS picker doing so.

Welcome also offers “Import Archive…” as a secondary action. Pick a .journalarchive file using the native file picker; then a scrollable native sheet asks for Recovery Key. Continue validates the entire archive before presenting journal names/counts and “Restore Journals”. Failure: “This archive couldn’t be opened. Check the recovery key and try again.” Corrupt content is distinguished after successful decryption: “This archive is incomplete or damaged. Try another copy.”

Import into an existing journal uses “Import as New Journals”: “Your current journals will be kept. Imported journals will be added as separate journals.” New IDs prevent overwriting existing work; image references/default templates/conflict and history references are remapped together. If no local journal exists, Restore Journals creates a local vault using the archive recovery key and preserves original identities. It does not copy server credentials or automatically connect to a server. Result copy, only at completion: “Journals Restored” / “You can set up sync in Settings.” / Done. Import is staged and atomically committed; failure keeps current journals untouched and allows retry. Cancel remains available before final import; while importing show “Importing Journals…” and prevent duplicate submissions. Lock cancels before commit and hides previews.

## Readable entry export
More > Export Entry… is available on both platforms. A compact native sheet offers “Readable Document” (HTML with embedded original images, headings, emphasis, lists and links) or “Journal Entry” (lossless portable JSON including original image data). Explanation: “These files aren’t encrypted. Share them only with people you trust.” Export uses the native Files/save picker. It captures the current draft even after a failed local save; missing image bytes cause failure rather than silent omission. Unknown document content is preserved in lossless JSON; readable export is disabled for unsupported versions with “Update Journal to export this entry as a readable document.”

Save-failure alert offers Export Entry… on both platforms; exporting does not silently clear or discard the unsaved draft. Recovery setup gains Save Recovery Key… using a native plain-text export picker, with the same existing explanation to keep the key safe.

## Accessibility and verification
Forms scroll with Dynamic Type; field labels are explicit, keyboard focus remains on invalid key, and text is selectable. No fixed-height explanatory text. Native cancel/action ordering and semantic colors. Inspect picker launch, wrong key, missing image, large text, dark appearance, app lock during import and storage failure; verify restored styling, image bytes, deleted state and retained conflicting versions in tests.

## Preservation boundary and copy — revision 2
Before final additive import, flush the current draft successfully, then block editing/navigation through the model for the entire snapshot/commit operation. A failed flush leaves the draft intact and blocks import; offer the existing Try Again / Export Entry… actions. Dismissing import returns to the same draft. Staging copies all current content only after that boundary. Additive import preserves the destination's recovery key, PIN and biometric configuration and re-encrypts imported data under its key; the entered archive key unlocks only the source. Existing connection credentials remain the destination's credentials.

Validation preview shows journal names, live-entry count and Recently Deleted count separately. Final action is Restore Journals for a new vault, Import as New Journals for an existing vault. For a connected destination add: “Imported journals will also sync to your server.” The completion title is Journals Imported for additive import, without setup guidance; Journals Restored and optional setup guidance only for a new vault.

Before import starts, Cancel discards only staged work. During final import/commit Cancel is unavailable and progress is labeled. Lock before commit abandons the staged import, preserves current data/draft and hides the preview; after unlock the user can reopen Import Archive and retry. No completion is shown after interruption.

Missing-image export copy depends on evidence: only configured, pending downloads offer connecting to the server. Local missing/corrupt images use “Some images are unavailable. Restore them from another copy and try again.” Images referenced only by conflicts, version history and deleted records are included and validated too. Readable HTML escapes all journal text and attributes, permits only supported link schemes, embeds images as validated image data and never executes journal markup or fetches remote image URLs.

## Stable Export Archive button — 2026-09-30
Owner report: the button jumps when pressed, and a double click showed “…couldn’t be saved in the folder ‘tmp’ because a file with the same name already exists.” Causes: pressing inserted a “Preparing Archive…” row below the button for a moment (the row appeared and vanished for a small library), and the button was enabled again as soon as the archive was prepared, before the save dialog appeared, so a second press prepared a second archive and asked the system save dialog to write another file with the same suggested name into its temporary folder. The raw system error was then shown.

- **Layout.** The Export Archive… row keeps its size and position. Progress is a small spinner at the trailing end of the same row, labeled “Preparing Archive…” for VoiceOver. It appears only if preparing takes longer than 0.3 seconds, so small libraries go straight to the save dialog with no visual change. While the spinner shows, the button is dimmed (disabled).
- **Repeated presses.** One export at a time: a press while an archive is being prepared, or while the save dialog is being shown, does nothing. The button accepts presses again once the dialog closes. Same on the Mac (save panel, Settings and File ▸ Export Archive… sheet) and iPhone/iPad (export picker).
- **Temporary files.** Each export prepares its own uniquely named package in the app’s data folder and removes it once the dialog reports saving or failing, when the app locks, or when the view goes away. A cancelled dialog doesn’t report back, so its package is removed when the next export starts. iPhone and iPad also keep the dialog’s own copy under the suggested name after a cancel, which made the next export that day fail with the “tmp” error even without a double click; that copy is removed before the dialog opens again. At every launch (once per process, before any export can start), the app also removes copies left by earlier builds or an interrupted export: only folders named `export-<UUID>.journalarchive` directly in its data folder and `Journal Archive <yyyy-MM-dd>.journalarchive` directly in its own temporary folder. Files, links, other names, subfolders, the library and saved archives are never touched.
- **Errors.** Shown in the existing red text below the button, never as a raw system message, file name or folder. Preparing failed: “Couldn’t export the archive. Try again.” Not enough space: “There isn’t enough space to export the archive. Free up space, then try again.” Saving to the chosen location failed: “Couldn’t save the archive. Try again, or choose another location.” App-authored messages (such as “Save your changes before exporting an archive.”) are kept. Cancelling the dialog shows nothing.

This keeps the reviewed flow, controls and copy apart from the new error wording, so no separate review round was held (contained fix per the owner’s request).

## Import Archive while the app locks — 2026-10-01
Red-team finding MAC-1: the Mac's Import Archive file panel stayed open over the lock screen, and a file chosen there opened the import sheet in its locked state, which had no button (Escape still closed it). Locking now closes the panel and ignores a file chosen while locked or while the library is being replaced. The locked import sheet shows the heading “Import Archive”, the existing line “Unlock My Journal to import an archive.” and a trailing Cancel (Escape). An independent design reviewer approved this layout; it adds only the standard dismiss control, so no further review round was held.
