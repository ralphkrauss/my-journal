# Device connection completion

Extends approved screens revision 2. Settings adds a native Devices tab beside Sync. With no server: “Connect to a server to add your other devices.” and Connect to a Server…. Connected: native list of device names, current device marked “This Device”; revoked devices excluded. Add Device… opens a sheet with Pairing Code, Continue, Cancel. Lookup then shows code and name, “Confirm this code matches the new device.” and Add Device / Cancel. Revoking another device asks “Revoke access for [name]?” with “This stops future sync. Journals already downloaded to this device cannot be erased remotely.” Current device has no revoke control here.

Existing-server connection offers Add This Device (default) or Recover Journals. Add This Device displays the expiring code, “On a connected device, open Settings > Devices > Add Device.” and “Waiting for approval…”. Cancel ends local polling; the unapproved server ticket expires. Expiration displays “This pairing code has expired.” and Get New Code. Poll errors retain address and allow Try Again. Existing local content requires Upload Local Journals before either path begins. Approved import uses a staged local vault and atomic configuration switch; local originals remain until successful switch. Approval received while app locks never installs data or displays journal content.

Forms/sheets scroll at large text sizes; no fixed text heights. Code supports selection/copy and VoiceOver reads the code digits. Busy operations disable duplicate actions and show labeled native progress. Every Settings sheet gates on locked state. No journal data appears in the pairing interface.

## Lifecycle and error decisions (revision 2)
Cancel or app lock cancels the requesting task, abandons its private key, and sends a best-effort ticket cancellation authenticated by the poll secret. The server serializes cancellation with approval and revokes any device created for that ticket. Even if offline cancellation fails, the abandoned private key prevents the client accepting a late grant; the ticket expires. Reopening starts a new code. Local journals remain intact. During final import Cancel is disabled to avoid interrupting an intentional upload; app lock cancels and prevents the final local configuration switch. Recovery/upload consent never changes silently.

A failed import retains the already received grant while this unlocked sheet remains open: “Couldn’t finish connecting. Your local journals remain on this device.” / Try Again. Retry reuses that grant, creating no additional server device. Closing the sheet abandons/cancels it. Network failures: “Couldn’t connect to the server. Check your connection and try again.” / Try Again. Lookup not found: “That pairing code wasn’t found. Check the code and try again.” Final approval/poll expired: “This pairing code has expired.” / Get New Code on requesting device; approving device offers Change Code. Revoked approval authorization: “This device no longer has access.” / Connect Again. Connect Again opens recovery/pairing without discarding local data; reconnecting the same vault retains local items and reconciles revisions.

The device list shows Added [date and time] and a short device ID under each name; revoke confirmation includes that ID. A failed revoke leaves the device in the list and shows “Couldn’t revoke access. Check your connection and try again.” / Try Again. Initial list load shows Loading Devices…; errors keep previously fetched rows and offer Try Again. A code is displayed grouped visually, Copy Code copies only digits, VoiceOver reads spaced digits.
