# Entry export accessibility review

## Independent proposal review — 2026-09-21

**Approved for implementation with the accessibility semantics below.** Independently inspected `entry-export-accessibility.md`, `ExportView.swift` and `artifacts/native-export-large-probe/evidence/B3DA1AD4-FB87-4F57-A523-708A6231790A.png`. The actual largest dark frame confirms vertically clipped “Readable Document” and an Export action broken inside its word. The current scroll view alone does not prevent the compact picker/action layouts from constraining their labels. This is a concrete usability defect, not a reason to reduce the user's text size. No test run or live interaction was performed in this review.

Two stacked full-width native format choices with a checkmark are appropriate for the two mutually exclusive formats at accessibility sizes. Keep the explicit Format group label, complete existing names and clear selected state. Each entire row should be one operable accessibility element with its full name, button role and selected trait only when selected; hide the decorative checkmark from separate accessibility navigation. Preserve selection with both touch and keyboard activation. Allow multiline text to determine row height, give the text available width before allocating checkmark space, and avoid fixed heights or a hidden one-line limit imposed by the button label style.

Stacking progress, Export… and Cancel removes the observed width competition. Retain the prominent Export action, native Cancel role and full-width hit areas; let each label wrap without shrinking. Keep every control reachable through the existing scroll view at maximum text size and small sheet dimensions. Disable format changes while preparing or while the system exporter is active. The action must not start duplicate preparation/export while already active. Do not collapse explanatory, error or unsupported-document text to make the actions fit.

The exact existing copy is suitable: “Export Entry,” “Format,” “Readable Document,” “Journal Entry,” “Export…,” “Cancel,” “Preparing Export…” and the existing plain-language unencrypted-file explanation. Selecting a format should only change selection. No new confirmation, instructional paragraph or custom navigation is warranted. Keeping the ordinary-size native picker/actions is appropriately scoped; serialization, encryption, filename, lock and system-save behavior remain unchanged.

### Acceptance evidence

Inspect actual normal and largest dark states with each format selected, all format names and selected indicators visible, and the complete Export/Cancel labels reachable by scrolling. Verify the system save flow using its active controls, rather than accidentally tapping the underlying sheet. A local synthetic export should preserve the source entry and produce the intended bytes/type; cancellation should leave source content intact and permit retry. The earlier probe's reported wrong Cancel target does not establish an app export failure. Busy/error/unsupported semantics deserve source inspection even if not all are visually driven. VoiceOver announcements, keyboard-only Mac navigation, browser rendering and live Mac remain separate evidence. Implementation/source and corrected rendered review are pending; no production code was changed here.
