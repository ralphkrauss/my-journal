# Version-history recovery

The existing entry sheet can dismiss after a failed save, has no owned restore task, and copies the historical parent without checking current journal availability. Journal metadata history is read-only. Replace these gaps with explicit native recovery using existing versioned encrypted records and owned mutation coordination; no new document format.

## Entry and template history

Capture the source ID and kind when opening Version History. Show native loading, No Earlier Versions, and retryable read error states distinctly. Use the familiar version picker with date/time and an ordinal for equal timestamps. Preview selected historical text, styling and available images read-only. Missing image bytes remain preserved references. Unsupported historical content remains read-only/exportable; say “Update Journal to restore this version.” Clear previews and cancel pending work on lock. A changed root selection does not retarget the captured sheet.

For entry history, show a Journal destination picker with only supported live conflict-free journals. Preselect the current source's live journal when possible, otherwise require explicit selection. Never silently choose an unrelated journal. Offer New Journal using the existing captured nested creation flow; creation does not automatically restore or select the destination. When none is available say “Create a journal to restore this version.” Restore as New Entry makes a new identity with the historical title, document, image references and journal date, clearing deletion markers and assigning the chosen journal. The original entry and every historical/conflicting version remain untouched. This may copy a supported historical version even when the current source or old parent is deleted, unavailable, unsupported or conflicted: it is explicit recovery into a valid destination, not overwriting or resolving the source.

For template history use Restore as New Template, with no journal picker. Preserve the historical title/content, clear tombstones, create a new template identity, and leave journal default-template links unchanged. Do not inadvertently turn a template into an entry.

Restore revalidates the selected historical record actually exists in this vault and validates the destination's current support/live/conflict state in the same transaction as creating the copy. A missing/changed historical version says “This version is no longer available. Reload its history.” Deleted/unavailable destination says “Choose an available journal.” Destination conflict routes Review Changes without copying; returning requires deliberate restore. Newer unrelated source changes do not invalidate immutable historical content.

Only one owned restore operation can run. Disable repeat restore and dismissal while committing. A precommit failure retains the selected version/destination and offers meaningful retry. A committed copy whose display refresh fails says “The version was restored. Reopen it from your journal.” (template equivalent) with Done and no repeat restore. On success adopt the canonical copy, refresh and navigate to it. Lock after durable commit must not lose the copy or rewrite the old editor snapshot. Cancel/Done without restore does not modify anything. The original history remains available through the existing lossless export.

## Journal metadata history

Keep the existing Version History metadata preview. Add Restore Settings for supported historical journal versions. Explain “Restore this name and default template. Entries and Recently Deleted status stay unchanged.” One confirmation shows the current and selected historical name/default template, with Cancel and Restore Settings. This changes only title and defaultTemplateID on the same current parent identity; it never replaces children, restores a deleted journal, or changes its lifecycle/date/document. Validate the current journal's supported/conflict-free metadata still matches the captured confirmation. Changed metadata requires renewed review. Missing historical template may be restored as its preserved reference (shown as Unavailable Template), without creating a template or silently substituting another.

Before patching, preserve the current journal version in encrypted history in the same transaction, so restoration itself is recoverable. Keep all existing immutable outbox retry bytes. Returning the canonical parent must reconcile into the model without entry autosave treating the journal preview as an editable draft. A committed refresh failure must not duplicate restoration; lock clearing and meaningful errors use existing patterns.

State that the current entry needs saving before restoration; only offer retry if it actually retries that save. Unsupported history offers the existing lossless Archive export within the active sheet, not a disabled Restore with no way out.

Journal settings restoration revalidates both immutable historical membership and the captured current journal in the same transaction. Changed current settings require reloading the current comparison and a fresh explicit confirmation; never retry using a silently updated expected snapshot. Conflicts open the existing review inside the active sheet. If the chosen name and default-template ID already match current settings, show “These settings are already in use.” and Done without a history or outbox write. Duplicate template names are distinguished in the comparison by date/context while their actual IDs remain the restore criteria; a missing template is shown as Unavailable Template without dropping its reference.
