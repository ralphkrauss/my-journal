# Image descriptions — native editing design

Proposal for independent review before implementation. Images already have portable per-block imageDescription metadata that survives native rich-text conversion and export. This fills the missing user-facing editing path, without adding tags, AI generation or a custom editor.

For an editable entry or template containing image blocks, More offers Image Descriptions…. It is absent when there are no images and disabled for read-only/locked/conflicted/unavailable content. Insert Image keeps its existing direct action. This adds no persistent controls to the writing surface.

Open a native sheet titled Image Descriptions with Done. Use a scrollable form, one section per image in document order. Each section shows a modest aspect-fit thumbnail (never enlarged beyond a reasonable preview), followed by a multiline field labeled Description. Use Image 1, Image 2, etc. as section labels when several images exist, and Image for one. VoiceOver identifies the preview as Image 1 and announces the existing description if available. The field's accessible name includes the image number. If attachment bytes are unavailable show a native photo placeholder and Image Unavailable; allow description editing for the preserved reference. Explain once in secondary text: “Describe what matters in each image. Descriptions help people using VoiceOver.” Empty is allowed; avoid mandatory prompts or generated descriptions.

Keep draft fields local to the sheet until Done; that single action applies the descriptions by captured block ID to the same entry, retaining every other document field and attachment reference. Cancel discards only description edits; Escape cancels on Mac. This is one deliberate small form save, not a second confirmation. Done flushes the existing entry first, revalidates the captured document against current state and refuses changed/removed images or changed descriptions with “This entry has changed. Review its images again.” Offer Reload Images to discard these field edits only after a native confirmation “Discard description changes?” with Keep Editing and Reload Images. Never overwrite text or newly arrived image metadata. The current entry’s text changes remain preserved.

Save through the existing owned mutation/flush/lock coordinator. While saving disable dismissal and competing edits. After success close; failed save keeps local fields and offers Try Again. Before a first save, Export Entry reflects the saved document; do not imply it includes unsaved sheet text. Use Copy Descriptions as the simple recoverable fallback for these local field edits, with clear keyboard-selectable text and no new file format. A committed update whose display refresh fails shows the saved outcome, disables repeating mutation, and offers Done. Captured entry change or lock cancels before commit and closes the sheet; committed data must reconcile before lifecycle flush. Do not leave hidden text retained after lock.

Use adaptive system text/surfaces, ordinary native buttons, flexible vertical layout, dynamic text size and keyboard focus. No hard-coded text heights. Focus the first description only on a deliberate edit action, not automatically when opening. Do not present thumbnails as decorative if doing so would hide the description context.

Verification: useful real-store/model regression proving only the intended image blocks change, current body/IDs/media references survive, repeated attachment use has per-block descriptions, stale images/descriptions reject, failed or locked mutations preserve data, and close/reopen plus native rich-text round-trip retains the descriptions. Inspect actual Mac and simulator form including dark/large-text/missing-image states and keyboard accessibility. The separate current large-text journaling E2E remains meaningful and should not be multiplied into a test for every layout property.

## Review revisions

Use an atomic store operation, not read-then-save of a full editor snapshot. Capture the entry ID and image roster in document order, including block IDs, attachment IDs, media types and original descriptions. Within one database write, load the latest supported record, require a live supported conflict-free parent for entries (or a live supported conflict-free template), verify the captured image roster and original descriptions, then patch only description strings into that latest document. Preserve all current text/runs/formatting and record fields. Reordered/added/removed/replaced images or changed descriptions reject without writing; unrelated body edits do not need to be overwritten or rejected. Return the canonical saved record for the model's owned reconciliation, after its existing final-draft save gate.

The sheet always has explicit Cancel and Done. While fields are dirty, interactive dismissal is disabled; explicit Cancel deliberately discards only these local field edits. When selection changes, the source is deleted/moved into an unavailable location, or conflicts arrive, keep the captured fields visible in this sheet, disable saving and offer Copy Descriptions. Say “This entry is no longer available for editing. Your description changes are still here.” Restored eligibility requires explicit Reload Images with the existing discard-changes confirmation, never an automatic rewrite. Reopening the same entry is not an implicit approval to apply old descriptions. Explicit lock is the privacy exception: immediately clear local fields, cancel pending work before commit where possible and dismiss. No hidden description strings remain retained after lock.

A stale description/roster error similarly retains all local fields and Copy Descriptions, plus explicit Reload Images. Refresh/display errors after durable save keep the saved outcome separate and never enable a duplicate save. Missing image bytes remain a thumbnail issue, not permission to remove the preserved block or reference.

## Shared core status

The atomic store operation is implemented as updateImageDescriptions(entryID, expectedImages, descriptions). It verifies the entire ordered image-block roster (including original metadata), checks target and parent lifecycle/conflicts, and patches only descriptions into the latest supported record. It preserves current text, title and attachment bytes. A real-store regression covers intervening body/title edits, repeated attachment IDs with distinct block descriptions, stale descriptions, image reordering, deleted-parent refusal, unchanged pending retry bytes and reopen preservation. The native form/model integration is now implemented and verified through real-store/model regressions and an actual simulator edit/save/relaunch flow. The model waits for existing autosave and rejects an unsettled draft; it does not initiate a full-record flush that could overwrite newer stored body text. See image-descriptions-implementation-review.md for independent review and precise native accessibility evidence limits.
