# Journal metadata conflicts — proposal

Independently approved in journal-conflicts-review.md; actual implementation and inspection remain required. This is a prerequisite for journal deletion and restoration, not a replacement for entry conflict review.

Settings > Journals displays a quiet “Changes need review” notice and Review Changes button in each affected journal section. A separate “Deleted Journals” section lists conflicted deleted journals by name so those conflicts remain reachable before Recently Deleted gains its full journal detail view. Name/default-template controls are disabled for conflicted journals; the notice supplies the recovery action.

Review Changes opens a native sheet pinned to the journal ID and the captured conflict version. macOS uses a title, scrollable content, and separate footer. iOS uses a NavigationStack with inline title “Review Changes”, Cancel in the cancellation toolbar and no fixed minimum width. Both use a segmented This Device / Other Device picker, then a readable version summary with Name, Default Template, and Location (“Journals” or “Recently Deleted”). A missing template name is “Unavailable Template”; nil is “Blank Entry”. Missing names use “Untitled Journal”. Values wrap and support text selection where supported.

The version header includes its modification date/time. The other-device header displays “Other Device · [first eight UUID characters]”; an accessibility label and selectable secondary detail expose the full recorded device ID to distinguish identities without requiring a network request. This is an identity from the conflict record, not a guessed device name. If device-name lookup is later added, it is supplementary and must preserve the ID fallback. Do not label a server receipt time as the user's edit time.

Use a native “Keep This Version…” button tied to the currently displayed captured version. Confirmation: “Keep this version?” / “Both versions will remain in Version History.” Actions Keep Version and Cancel. No Keep Both for journal metadata: duplicating a journal record does not duplicate or reparent its entries. A transaction rejects a changed local or remote baseline; inline error “These changes have been updated. Review them again.” and Reload Changes reload the conflict and reset confirmation. When another device already resolved the conflict: “These changes have been resolved.” and Done. Never automatically apply a stale choice.

While resolving, freeze selection/confirmation and disable dismissal; own the task through commit and model reconciliation. Lock immediately hides the sheet and clears its readable state; precommit cancellation is respected and a committed resolution remains committed. Save a current entry draft before beginning, with inline failure and the existing Export Entry recovery route. Postcommit refresh failure says the choice was saved and offers Reload. No global alert behind the sheet.

If either conflict version contains unsupported content, disable resolution and show “Update Journal to review these changes.” Offer a lossless export of the vault through the existing ArchiveControls route, which includes conflicts and history, instead of exporting only the selected journal metadata or silently dropping fields. The original versions remain preserved. The dedicated entry exporter is used only for the separate failed-entry-save recovery.

Version History is reachable in every live/deleted journal settings section that has stored conflict history, with the same metadata summary and a native version picker showing date/time and ordinal to distinguish identical timestamps. Initially history is read-only with the existing lossless vault export accessible from Privacy; explain “Earlier versions are included when you export your journals.” Restoring journal metadata from history is unfinished work and must not be implied by this read-only viewer. Resolution itself stores both originals transactionally. This proposal does not reuse the entry-only “Restore as New Entry” action for journal records.

Accessibility: system surfaces/type, native focus/toolbar roles, selected segment semantics, labeled fields, scrollable long names/enlarged text, no color-only distinction, inline errors announced. Test actual iOS interaction and offscreen Mac render; record interactive Mac/VoiceOver separately. Useful tests exercise stale resolution rejection, preserved history, keeping remote journal metadata without copying/reparenting children, lock around commit, and reachable deleted-journal conflicts. Avoid tests of ordinary field rendering.

## Review refinements

The action is “Keep Version…”. Opening confirmation captures the displayed local or remote item and its baseline; segment changes cannot alter that captured choice. Confirmation title is “Keep the version from This Device?” or “Keep the version from Other Device?” and message “[modification date and time]. Both versions will remain in Version History.” Remote Details includes the full recorded device ID as selectable text with an accessibility label. The primary header uses device label and edit date/time, with a native Details disclosure for the identifier. Date/time is formatted using the user's locale.

For unsupported content show “Export Archive…” directly below the update guidance, opening the existing archive export sheet inside this sheet. If the archive's prerequisite entry flush fails, retain the unsupported conflict and show “Save your entry before exporting the archive. You can export the entry separately.” with a separate “Export Entry…” action opening the existing lossless entry exporter. Export Entry does not resolve the journal conflict or clear saveFailure; retrying Export Archive attempts its normal flush again. Cancel remains available. These nested exporters dismiss/hide with lock and cannot leave readable journal state behind.
