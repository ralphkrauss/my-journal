# Whole-journal recovery UI — implementation design

This consolidates journal-deletion.md with the approved inherited lifecycle protocol, which supersedes its old cascade and Restore Journal and Entry wording. Shared store/agent/native visibility and metadata conflict review now exist and have passing focused tests. Permanent purge remains separate unfinished work.

Settings keeps each live journal section and adds Delete Journal…. This opens a captured-journal sheet titled Delete Journal, with the journal name, locally known affected entry count, and a destructive Delete Journal button. The sheet itself is the single confirmation surface and says “[count] entries on this device will move to Recently Deleted. Entries from other devices will appear there when they sync.” Zero uses “This journal will move to Recently Deleted. Entries from other devices will appear there when they sync.” Cancel is safe/default. Preparing the sheet flushes edits; preparation failure stays in the sheet with Try Again and lossless Export Entry if saving failed. No mutation before confirmation.

Recently Deleted has Journals and Entries sections, omitting empty sections, with the existing date groups retained for entries beneath Entries. Journal rows show the full name and local count of entries that will return on restore. Search matches journal names as well as entries; prompt Search Deleted Items. A selected journal uses a read-only detail, not the entry editor. The detail has name, local eligible entry count, Restore Journal, conditional Review Changes and Version History, and lossless archive export for unsupported metadata. Contextual copy once: Deleted items stay here until you restore them. An empty journal does not trigger No Deleted Items. Settings' deleted-journal sections also offer Restore Journal… so recovery stays reachable while Settings is open.

Restore Journal opens a captured-journal sheet titled Restore Journal. Show current name, local eligible count, and “Entries deleted with this journal will return, including entries that sync later. Entries you deleted separately will stay in Recently Deleted.” If locally known legacy-marker entries exist, show their count with “Restore these entries individually.” The sheet itself is the single confirmation; Cancel and Restore Journal are its only completion actions. Successful restore selects that journal and clears the old draft; independently deleted and legacy entries stay in trash. Restoration does not resolve child conflicts.

Both actions use one JournalLifecycleView with a fixed journal ID and action. Re-read the current record/plan to populate the confirmation sheet. A changed deletion name or locally live entry set at commit shows the changed-state error and requires Try Again followed by another explicit press of Delete Journal; never auto-submit. Restoration revalidates the captured name before committing; a changed name returns for fresh review. Sync updates may invalidate the plan but cannot replace an already displayed confirmation plan. Supported parent metadata only; unsupported content offers Update Journal to continue and lossless Export Archive. Typed conflict failures offer Review Changes in this active sheet, routing to metadata or entry review. On return, clear old confirmation and require renewed preparation. If the conflict disappeared, a native resolved message and Done prevent a blank sheet.

Owned asynchronous tasks disable mutation and interactive dismissal while running. Lock immediately hides the sensitive root, closes nested exports/review/confirmation, cancels before commit where possible, and the model owns committed reconciliation through lock flush. A committed operation whose refresh fails shows “The journal was deleted/restored, but couldn’t be displayed. Reopen Journal to try again.” It disables repeat mutation and offers Done, never suggesting deletion/restoration failed. Failed draft saving exposes Export Entry in the active sheet. User-facing errors are announced and are not communicated by color alone.

Use native scrollable forms, system adaptive typography/colors, no custom palette, with Cancel/Done in standard toolbar positions on iOS and keyboard shortcuts on Mac. Names wrap, counts handle singular/plural, buttons have ordinary VoiceOver labels. Journal row accessibility combines name, Journal, and restore count. Avoid a new independent navigation stack just for trash: select the journal ID using the existing split-view selection, with a journal-specific detail branch and canEdit remaining false. Existing entry export/format/delete actions must be disabled for journal selections.

Verification: focused native model regression for stale restore confirmation, last-journal delete/select/relaunch/restore and final-save/lock boundaries; existing real-store stale deletion/cycles/conflicts tests remain relevant. Actual simulator flow should delete the last journal, find its entry and journal in trash, cancel then restore, and verify the content survives relaunch. Inspect native sheet/detail/empty states and large text. Offscreen Mac remains limited evidence until the desktop is unlocked. No tests for static layout getters or arbitrary coverage.

## Review revisions

There is exactly one confirmation surface: the captured sheet. Its prepared name/count/scope and Cancel plus Delete Journal or Restore Journal are sufficient. No nested confirmation alert/dialog. Stale-state errors clear the prepared plan; Try Again refreshes the sheet and enables a new explicit action without automatically applying it. The destructive action has no default Return shortcut; Cancel retains Escape.

If preparation or an atomic rejection followed by refresh finds deletion already applied, show “This journal is already in Recently Deleted.” and Done without Try Again. If restoration already applied, reconcile navigation to that journal, show “This journal has already been restored.” and Done. An operation that atomically returns an already-applied state uses the same outcome rather than retrying. Missing parent shows the existing local-only/configured-sync unavailable guidance and export; no impossible retry loop. A later explicit sync can repopulate the record but does not automatically submit the pending action.

Every count says “1 entry on this device” or “[n] entries on this device.” Legacy copy says “[n] entries from an earlier version of Journal need to be restored individually.” Journal row accessibility includes its name; No Results/Clear Search takes precedence over No Deleted Items for an active search.
