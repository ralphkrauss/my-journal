# Writing and onboarding revision

Requested 2026-09-21. This supersedes the password-generation buttons, creation action strip and template-preview chooser in the earlier feedback design. Implement after independent review. Preserve native writing, accessibility and existing content; no new account requirement or publication.

## Onboarding and credentials

First sheet: **Protect Your Journals**. Intro, before controls: “Encrypt your journals so only you can read them. Your master password lets you recover them if you lose access to your devices.” Primary **Use Encryption** opens the password step. Secondary **Continue Without Encryption** is directly accompanied by “Anyone with access to your journal files or server can read your entries.” This skips every password step; no generated hidden user password and no confirmation alert. Cancel returns to welcome without creating data.

Password step: **Choose a Master Password**. “Save this password in your password manager. You’ll need it to recover your journals.” One native SecureField, new-password content type, paste allowed, no forced autocorrection/capitalization, system password-manager suggestions. Optional Show Password; no Generate or Copy buttons, no confirmation field. At least12 characters, disabled Create until valid; Cancel/back retains only transient field state. Creating… prevents duplicate submission; on failure keep form and password for retry. Never log it. Recovery fields use password content type. Suggestions depend on platform/provider; do not promise universal generation or storage without associated-domain support.

Plain libraries remain authenticated on servers. Use automatically provisioned cryptographically random device credentials through setup-code authentication and pairing; plaintext recovery must not expose an authentication secret through the public recovery-envelope endpoint. A new plaintext envelope version is required, with archive contents readable/restorable without a password, and server recovery through another authorized device or a local-server administrator reset procedure. Explain this in the connection/recovery screens. Existing encrypted and older plaintext/password libraries retain their credentials and remain readable; no silent conversion or key reset.

## Toolbar and creation

Restore native icon-only toolbar buttons for New Entry (square.and.pencil) and Templates (doc.on.doc). They form a native toolbar group associated with the entries column, never a permanent labeled strip inside the editor/list. Tooltips, accessibility labels and keyboard access retain the full names. Entry actions remain in their context menu on Mac; mobile retains its ordinary overflow route. At narrow widths use native toolbar overflow rather than overlap or clipped labels.

macOS Settings keeps the standard My Journal → Settings… and Command-comma route, with an additional gear-shaped toolbar shortcut. It opens the same Settings window. Remove the redundant sidebar Settings row. Mobile keeps its existing direct gear. No custom gear menu.

## Template choice

Mac: a compact anchored popover titled **New Entry from Template**, containing a native NSComboBox labeled **Template**, search/type-ahead, template names only, and Cancel/Create. No destination subheading, prose previews or Blank Entry item (New Entry already creates ordinary/default entries). Initially no selection; Create disabled until an existing template is selected. Typing filters names; duplicate names remain distinct by identity internally. No match: “No matching templates.” No templates: “Save an entry as a template to use it here.” Return accepts a valid selection; Escape cancels. Invalidated/deleted selections show “This template is no longer available.” and retain the picker. Capture destination journal and reject unavailable destination without creating elsewhere.

iPhone/compact iPad: native searchable list of names in a sheet, same title, Cancel/Create and selected checkmark. Regular iPad anchors that picker to the template button. No preview cards or ambiguous journal name. Keyboard focus returns to the chosen entry’s selected title after creation. The same picker is available from File → New Entry from Template….

## Formatting and Markdown

Canonical document content becomes Markdown. Define the supported dialect as CommonMark plus GFM tables, strikethrough and task lists; include six heading levels, strong/emphasis, inline and fenced code, quotes, ordered/unordered and nested lists, rules, links and images. Underline remains an explicit safe extension to preserve existing entries. No arbitrary active HTML. Markdown source must round-trip without silently losing unsupported or unknown syntax. Keep IDs, timestamps, attachment metadata and sync state outside the Markdown text; images use portable attachment-relative URLs. Existing block-JSON documents remain readable and are converted only at a deliberate successful save, retaining history and original recovery/export paths. Old clients must refuse newer documents rather than overwrite them.

The default writing surface stays native and formatted. A Markdown source editing mode is available from Format for exact syntax/complex constructs, with native spell checking, selection, undo and keyboard behavior. It must retain source verbatim on open/save without edits and allow every dialect construct. Never silently simplify tables, nesting, code whitespace or unknown HTML when switching modes; if a construct cannot be safely represented in the rich editor, retain it as a visible source block or keep the document in source mode with a concise explanation. No rendered web content, remote image fetching or HTML execution.

The formatting popover follows Notes: compact visual hierarchy, clear typographic examples, grouped inline-style controls, list choices and light dividers. No oversized margins or card-style rows. Whole rows/segments own the hit area. Bold/italic/underline/strikethrough/code expose current and mixed states. Include Heading1–6, Body, quote, lists/checklist, code block, rule, table, Link… and Image… through orderly native groups/submenus rather than one long wall. Tables start as a small valid Markdown table that can be edited in source; never pretend unsupported rich-cell editing exists. Images retain existing picker/description behavior. Repeated clicking the toolbar control toggles presentation; Escape/outside click dismisses; selections are captured and validated against the entry/session.

Keyboard: native Format menu commands display shortcuts (Command-B/I/U/K, Command-Option-1…6 for headings, Command-Option-0 for body, Command-Shift-X for strike); add a searchable Format command picker via Command-Shift-P, also usable with an external iPad keyboard. It lists styles by familiar names with shortcuts and applies only after explicit selection/Return. Typing ordinary text never triggers a slash command, automatic Markdown replacement, or unsolicited popup. Escape cancels without mutating text. This avoids interfering with prose, URLs, code and IME composition. Syntax insertion in source mode wraps selection/places caret intelligently and is one undoable native edit.

## Destructive actions

Deletion uses role.destructive, a trash icon where useful, and native destructive/red emphasis on the final button and journal-management action. Keep the existing confirmation explaining affected entries and recovery. Cancel is the safe/default action; deleting is never the Return default. Use system semantic red and sufficient contrast; do not depend only on color. Never recolor every action or make destructive controls prominent in the writing toolbar.

## Verification

Meaningful tests: passwordless creation/reopen/archive/pairing and unauthorized server rejection; old credential compatibility; Markdown round-trip for nested lists/tables/code/escaping/marks/images and preserved unknown syntax; legacy conversion/history; native formatting selection/undo and no text-trigger interference. Inspect actual Mac toolbar, picker, whole-row hit targets and onboarding, then compact/regular mobile layouts and large text. Run one build/test workload at a time with limited parallelism. Shut down simulators/review apps/helpers after checking; preserve user data and useful evidence.

## Review clarifications (supersede alternatives above)

Opening copy: “Encrypt your journal files to protect your writing. Your master password lets you restore a backup or connect another device.” Below the password: “Use at least 12 characters.” and “Keep a backup of your journals too. Your password cannot replace lost data.” Password starts hidden. Back retains transient input; Cancel clears it. Failure: “Your journal couldn’t be created. Try again.” No staged configuration is installed until writes succeed.

Passwordless journeys: offline creation needs no network/credential. New server setup asks only Server Address, Setup Code and existing Upload Local Journals consent. Existing server: Add This Device/pairing works normally and shows “Your entries aren’t encrypted. Approve this device from another connected device.” Recovery alternative is labeled **Use a Recovery Code** with field **Recovery Code**, explanatory copy “Ask your server administrator for a one-time recovery code.” This build will include `--recovery-code`, executed with local server-file access, rotating a random code hash for a version4 library; successful use consumes the code atomically. The public envelope contains no key or secret. Plain archive import states “This archive isn’t encrypted. No password is needed.” and proceeds to the same content preview; it installs no server credentials. Passwordless libraries retain optional App Lock. Their lock screen offers **Unlock with This Device** as the forgotten-PIN fallback, using native device-owner authentication (system password/passcode or biometrics), never an invented journal password. Cancellation/failure stays locked. Privacy explains “App Lock restricts access in My Journal. Your journal files aren’t encrypted.” Encrypted/legacy recovery stays unchanged. Legacy PIN/encrypted/v3 libraries keep existing unlock/recovery behavior.

Markdown editing matrix: headings1–6, strong/emphasis/underline/strike/inline code, paragraphs, simple lists/tasks, simple quote paragraphs, rules and local images are editable in formatted mode. Nested lists/quotes, tables, multiline fenced code, reference-link syntax, remote images and arbitrary HTML are fully editable as Markdown source; they are not flattened into a rich approximation. If any unsupported rich construct is present, the **whole document** stays in source mode. It says “This entry uses Markdown source to preserve its formatting.” It never silently switches mode due to typing. In this mode ordinary source insertion works; **Formatted Text** is disabled with that explanation until content can be represented safely. **Markdown Source** is a toggle in Format on Mac and at the bottom of the formatting sheet/popover on touch. Toggling without an edit preserves exact stored source; mode transitions preserve a sensible caret near the same block and coherent per-entry undo across both modes. Use the same native text view/storage; switching presentation is an undoable attributed-text change with mode metadata, not destruction/recreation of the editor or its undo manager. Undo/redo must restore both the prior presentation and document. Switching alone never drops edit history. Never convert on opening, date/title changes, sync, history viewing or export. New bodies store version2 Markdown; legacy document versions remain legacy until the first actual body edit/format action, whose store transaction records the previous version before replacing it. On failed persistence, the existing save-failure draft/retry UI remains; persisted legacy content is intact. A legacy construct that cannot be converted keeps its original representation and update/read-only export route.

Markdown uses relative `attachments/<uuid>` image destinations and `<u>text</u>` only for underline. Other HTML remains inert source. Record/document metadata stores stable block/image IDs and media types, never an alternative authoritative body. Source editing retains exact user bytes. Rich editing reuses unchanged original source segments by stable block identity; only actually changed/inserted blocks are serialized, retaining unrelated spacing and escapes. Complex/reference/unknown syntax uses source-only editing, so adjacent edits are native string replacements. History, conflicts and templates carry the complete versioned document; mixed legacy/new versions remain distinct and recoverable. Archive and Markdown export retain text and attachment references. Old clients encounter document version2 and refuse editing it; test the actual v1 decoder boundary.

Formatting layout: row1 B/I/U/strikethrough/code segments; divider; paragraph examples **Title**, **Heading**, **Subheading**, **Body** (H1/H2/H3/paragraph), plus **More Headings** submenu for H4–H6; divider; Bulleted List, Numbered List, Checklist, Quote; divider; **Insert** submenu for Code Block, Divider, Table, Link…, Image…; divider; Markdown Source and **Find Format…**. No fixed height on touch: medium/large detents, scroll, reachable Done. Mac popover is compact with scrolling if the system text size demands it. Find Format presents **Format Text**, search placeholder “Find a format”, name-only rows, “No matching formats.”, Cancel and Apply; highlighting never changes content, Return applies only a selected existing command. Command-Shift-P opens this picker only when the entry editor owns focus; ordinary field/navigation/IME shortcuts win. On iPad external keyboards, standard inline shortcuts remain native and explicit picker entry is available without requiring shortcut support from the OS. Optional unsupported external shortcuts are not advertised.

Source commands wrap a selected range or insert valid syntax at the caret with one undo step. Block commands act on complete selected lines. A source-only document never runs a rich formatting conversion. Inside a code fence or inline code, unsafe inline/block transformation commands are unavailable with “Move the cursor outside code to apply this format.” Empty selection inserts paired delimiters with caret inside; links use the existing Text/Link dialog. Table/Code Block are explicit commands switching to source mode, not keystroke-triggered changes. Raw HTML is never evaluated or remote images fetched.

Template combo: initial empty field with placeholder “Choose a template”; focus in combo. Arrow keys choose native dropdown suggestions. Return while dropdown open commits the highlighted live ID and closes only the dropdown; a subsequent Return/Create creates. An uncommitted/custom string cannot create. Edits invalidate previous selection until matching an actual suggestion. Cancel/Escape closes with no write. Duplicate names show a short unique ID suffix only on collision, with the full name and identifier accessibly; existing titles are unchanged. Destination loss: “This journal is no longer available. Close this window and choose a journal.” Template loss clears the choice and shows “This template is no longer available. Choose another template.” Ordinary New Entry still uses the journal’s default template; New Blank Entry remains in File.
