# Move Entry — implementation proposal

Extends the already reviewed journal-management design. Scope here is moving an existing entry between journals and fixing the Manage Journals destination. Journal deletion/restoration and image-description editing remain separate required work.

More > Move Entry… appears for a live, editable entry, beside Export Entry and before Delete Entry. It is disabled for templates, deleted/unsupported content, lock, and vault replacement. This is a move of the same entry identity, retaining dates, text, images, history, and sync state; it never copies or deletes the body.

The native sheet is titled “Move Entry”. A scrollable native list shows other live journals using their names, with a checkmark for the selected destination. No automatic default destination. Native accessible button rows announce selection; keyboard and VoiceOver can select a journal. Cancel and Move stay outside the scrolling content on macOS; iOS uses native navigation toolbar Cancel and Move. Move is disabled until a destination is selected, and throughout the operation. Native adaptive backgrounds/fonts; no custom palette or fixed content heights. macOS ideal size420×360, resizable content; iOS respects Dynamic Type and safe areas.

With no other journals, show “No Other Journals” and “Create another journal in Settings to move this entry.” Cancel remains available; Move stays disabled. Manage Journals from the sidebar must open the Journals settings tab directly (currently it opens whichever tab is initially selected). The ordinary Settings action retains the last selected tab.

On Move, flush the current draft before changing its journal. Freeze mutations during the short operation and disable interactive dismissal once committing. Check lock/cancellation and that the entry/destination are still live before committing. Reject unresolved entry conflicts with “Review this entry’s changes before moving it.” A removed destination gives “That journal is no longer available. Choose another journal.” Preserve the sheet and selected destination on a recoverable error, show error inline, and re-enable Move only for an available choice. Failed local save retains the draft and offers the existing save/export recovery path; no false success or selection change.

On success, close the sheet, switch to the destination journal, and retain the moved entry selected. Local commit is success even if a subsequent display refresh fails; explain that distinction and do not retry the move automatically. Background sync follows the existing quiet behavior. If lock occurs, dismiss and hide the entry; a move committed before lock remains committed, an uncommitted operation must not proceed after the lock check. Cancel before Move makes no changes. No extra confirmation: moving is reversible by moving the entry back.

Verification: meaningful persistence test with a last-second edit and image, same identity/history, reopen in destination; invalid/deleted destination and unresolved conflict must preserve the entry. Native rendered/interactive inspection after implementation, with evidence boundaries stated honestly for locked macOS desktop. iOS E2E should exercise the actual picker and reopen the moved entry.
