# Native implementation source review

Date: 2026-09-20  
Reviewer: independent design agent  
Scope: `AGENTS.md`, approved `screens.md` revision 2 and `screens-review.md`, compared with `apps/apple/JournalApp`.

**Outcome: material departures require correction.** This is source-only evidence. The Mac is locked; no running macOS or iOS UI, keyboard behavior, VoiceOver output, layout, or appearance was inspected. It does not satisfy the mandatory actual-UI inspection gate. Findings cover previously agreed features only.

## Blocking preservation and access findings

1. **P1 — Failed-save recovery cannot prevent loss on close/quit.** `Views/RootView.swift:31` offers Try Again and OK; its persistent failure state at line 160 only says to keep the app open. `JournalApp.swift` has no close/termination interception or export action, and only flushes on background. A user can dismiss the alert and close/quit before persistence succeeds, or quit during the debounce. Implement the reviewed Keep Open / lossless Export Entry… close flow and reachable recovery actions. Include images and formatting in export. Keep the failed draft pinned as the existing selection guards intend.

2. **P1 — Lock does not gate the separate Settings scene.** `JournalApp.swift:65` always constructs `SettingsView`; that view has no locked-state guard, and its Privacy tab can call `setPIN` without authenticating the current lock. An already-open Settings window can remain after locking, and Settings can be opened while the root is locked. `AppModel.setPIN` also lacks a locked guard. Gate every window/sheet and privileged mutation on unlocked state; dismiss or replace settings and conflict sheets on lock. On macOS, the reviewed session-lock/inactivity lock path is absent. Verify no settings or conflict content survives lock visually.

3. **P1 — Text sharing a paragraph with an attachment can be silently discarded.** `Editor/RichText.swift:109–110` converts an entire paragraph to one image block whenever its first character carries `.journalImage`. Any text typed after that attachment in the same paragraph is then omitted from the persisted document. Conversely, attachments later in a paragraph are not extracted by this path. Native editing can remove the newline around an image. Preserve every text run and attachment when converting mixed paragraphs, or enforce a lossless editing boundary. Exercise deleting the newline before/after an image, typing on either side, and reopening the entry.

4. **P1 — Upload consent is missing for an uninitialized server.** `ConnectionView.swift:25` presents Upload Local Journals only for initialized servers. The Set Up branch calls `AppModel.initializeServer` at line 301, which immediately connects and syncs existing local content at line 312. Add the approved explicit upload choice and explanation before this path uploads; cancel must retain local mode.

5. **P1 — Missing device key points to an unreachable recovery flow.** In `AppModel.load`, a missing Keychain key throws before setting `locked` or constructing `store`. `RootView` then displays the welcome screen because `store == nil`, with no local recovery-key unlock action, despite the error telling the user to use their recovery key. Provide the reviewed local Recovery Key entry path for this state and prevent Start a Journal from replacing the existing configuration as a workaround.

## Material usability and completeness findings

6. **P1 — Conflict choices hide meaningful differences and promise inaccessible recovery.** `Views/SettingsView.swift:96` renders only `document.text`; formatting and inline images cannot be compared. The selector/action labels use generic This Device/Other Device instead of actual device/time, and confirmation at line 111 promises Version History although no history entry point exists. Use a full read-only document preview, unambiguous device/time labels, the reviewed history/Restore as New Entry action, and visible handling for a newly arrived version during review. Flush and preserve an actively edited draft before resolution. Verify both versions remain fully inspectable at minimum window size.

7. **P2 — Several approved flows are not reachable.** The current settings/timeline/toolbars omit Move Entry…, journal deletion/restoration, Delete Permanently…, Devices/Add Device/Revoke, Agent Access, and Set Up on This Mac. The connection sheet offers only Recovery Key for initialized servers, with no existing-device approval path. These should remain explicitly unfinished until implemented and reviewed in the actual UI; do not label the agreed feature set complete. Restore currently silently restores a deleted parent journal rather than presenting “Restore ‘[journal]’ and Entry.”

8. **P2 — Image descriptions and accessible document structure are incomplete.** Images are inserted with an empty description and there is no Description editor. Rich-text headings use font changes/custom attributes without an explicit accessibility heading representation; attachment descriptions are not exposed to accessibility, and iOS missing images are rendered as a bitmap label. Implement the reviewed image description flow, retain its text for missing images, and verify headings/descriptions with VoiceOver. Source does not establish usable semantics.

9. **P2 — Creation/search/navigation affordances are incomplete.** `.focus` exists in `NativeEditor`, but no creation action invokes it; new-entry body focus is therefore not established. The app has no explicit Find/⌘F command that reveals and focuses sidebar search. Manage Journals opens the general settings sheet without selecting its Journals tab. Implement the specified focus/command/tab targeting and inspect actual iPhone push/back navigation and sidebar-hidden behavior.

10. **P2 — Error and settings copy can mislead.** Connection validation collapses invalid addresses and incompatible versions into a generic connection failure. Sync displays raw error descriptions rather than the reviewed statement distinguishing saved local content from failed sync. The biometrics toggle is shown without checking availability and names both Touch ID and Face ID on every platform. Recovery-key setup lacks Save Recovery Key…. Apply the approved contextual copy and actions, taking care never to claim durable local saving while `saveFailure` is true.

## Required actual-UI verification after corrections

Inspect macOS at 640×420 and iPhone portrait with keyboard and enlarged text; native focus after creation and sheet dismissal; full-content conflict previews; images when the editor width changes; VoiceOver heading/image descriptions and error announcements; lock while sheets/settings are open; and failed persistence followed by navigation, lock, close, and export. Test light/dark and supported contrast/transparency preferences. Source review alone cannot approve these behaviors.

## Follow-up review — implemented iPhone screen and source fixes

Date: 2026-09-20. This section supersedes the original status where stated. ### Visual outcome

**The pictured ordinary editor is approved visually.** The native back control and grouped toolbar, system typography, neutral surface, left-aligned date/title/body, and restrained copy match the agreed direction. Text is legible, controls have ample separation, content fits the safe area, and the writing surface is quiet. No concrete clipping, overlap, contrast, or unnecessary-copy defect is visible. Keep this layout; there is no evidence-based reason to add decoration or persistent explanatory copy. The large unused writing area is appropriate for a short entry.

### Resolved and partially resolved original findings

- **Finding 1, partially resolved:** `WindowSafety.swift` now intercepts macOS close/termination, flushes, and offers Keep Open / Export Entry…. Its export includes the structured entry and referenced attachment bytes, and explains that the export is unencrypted. This addresses the source-level absence on Mac; verify failure behavior with the real window. iOS still has no complete-entry export action, and the inline failed-save state only offers instructions plus the generic alert. The More-menu export is macOS-only.
- **Finding 2, partially resolved:** Settings now replaces its content while locked; `setPIN` rejects locked calls. The Mac observes session lock, and the root gains an inactive privacy overlay. However, `RootView` presents Version History outside the unlocked branch; that sheet caches full journal versions in local state and has no locked-state guard or dismissal. **P1 remains:** cover/dismiss every presented journal sheet when locking; a root overlay cannot be assumed to obscure a separately presented sheet. Configurable inactivity lock is still absent.
- **Finding 3, substantially addressed in source:** the converter now splits native paragraphs around attachments and preserves neighboring text, rather than treating the whole paragraph as one image. Verify native typing after an attachment and deleting its adjacent newline. A residual concern remains in `textDocument`: it still treats a leading `.journalImage` attribute as an image without checking `.attachment`; ordinary text inheriting that custom attribute could still be misread. Normalize/clear attachment-only attributes from typed text or demonstrate the native editor does so. This is a targeted remaining preservation check, not a request to change the layout.
- **Finding 4, resolved in source:** Upload Local Journals and its explanation now appear for both server branches, with submission disabled until selected when local content exists; initialization receives the consent value.
- **Finding 5, resolved for the missing-key nil result:** loading a missing key sets `locked`, and Start a Journal rejects an existing configuration. The recovery-key action is therefore reachable without replacing the existing journal. Verify failed Keychain reads separately from a nil result.
- **Finding 6, partially resolved:** conflict previews now use the rich editor, and More > Version History offers Restore as New Entry. Review flushes before opening. Actual device names/time-qualified choices remain absent, and `.id(showRemote)` reconstructs the preview rather than retaining each version's scroll position. A changed remote version has no dedicated notice. These remain departures from the reviewed conflict flow. Conflict/history previews also hard-code font size 17 instead of following the main editor's display-size preference/Dynamic Type.
- **Findings 7–10 remain open unless noted above.** No new evidence establishes the missing management/device/agent flows, image-description editing, heading/image accessibility semantics, body focus after creation, Find command, direct Journals-tab routing, contextual error copy, biometric availability handling, or Save Recovery Key….

### Small concrete copy/accessibility corrections

1. Keep ordinary editor copy as pictured. In the connection sheet, remove the unconditional Tailscale/tailnet instruction from the initial generic server form; it introduces hosting-specific jargon even when the user is connecting to another server. Server Address and contextual connection errors provide the necessary action.
2. Display the available biometric name, such as “Use Face ID” or “Use Touch ID,” only when supported. “Use Touch ID or Face ID” is imprecise on a known device.
3. Make conflict choices identify the device and modification time before the destructive selection is confirmed. Generic “Keep this version?” does not fix ambiguous version identity.
4. Verify Aa, image, More, back, date, and title with VoiceOver. Their recognizable appearance is not evidence of accessible names, reading order, or reachable formatting controls. Verify large accessibility text with the keyboard shown and conflict/history sheets open; the screenshot cannot approve these states.

**Overall follow-up outcome:** the pictured main writing screen meets the visual direction; the application as a whole still has material interaction, preservation, and accessibility work before full design-gate completion. No implementation edits were made during this review.
