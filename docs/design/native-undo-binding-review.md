# Native macOS undo and document binding review

## Independent proposal review — 2026-09-21

**Approved for implementation with the reconciliation conditions below.** Inspected `native-undo-binding.md`, `EditorIsolationTests.swift`, the macOS coordinator in `NativeEditor.swift`, and `/tmp/journal-editor-isolation-mac4.log`. The log records native visible text restoration without failure at its text assertion, but exact bound-document failures after Undo on both entries. This supports a real correctness gap in the production-rich-text configuration: autosave can otherwise retain content different from the visible editor. No tests were rerun and no interactive Mac behavior was inspected.

Observing the native UndoManager's completed undo/redo notifications is a suitably narrow correction. It preserves platform menus, shortcuts and native history rather than replacing Undo with a second journal-specific stack. There is no new layout, copy, focus or accessibility interaction requiring a mockup. Registering once per coordinator and filtering by the current view's manager identity is essential because the notification registration is process-wide. Selector-based cleanup is appropriate; do not add asynchronous deferred reconciliation that can outlive entry ownership.

### Implementation conditions

- Reconcile synchronously only when the notification object is identical to the current native view's UndoManager, with an attached current view and the existing applying guard. Keep entry-switch history clearing and stale-formatting-session rejection intact. A notification from another manager must not touch this binding.
- Convert the completed native attributed content through the same document conversion as ordinary text changes. Keep rendered state consistent with that result before publishing the binding, avoiding a subsequent SwiftUI update that restores stale content. Do not render a new attributed string, reposition selection, reset typing attributes or register another undo operation merely to synchronize the binding.
- Explicitly force image presentation refresh on this completed-undo/redo path. The manager may no longer report `isUndoing`/`isRedoing` when its completion notification arrives; relying only on the current `textDidChange` expression can leave an undo-restored attachment with stale loading/image presentation. Preserve the existing image refresh protections for composition, metadata, selection, viewport and undo registration.
- Native delegate and completion callbacks may both fire for the same edit. Avoid treating an unchanged converted document as another user edit if the existing callback is shared or refactored; at minimum ensure reconciliation cannot create an extra undo step or feedback loop. Do not expand this into an unrelated autosave refactor.

### Verification and scope

Use the failing real-native test with `isRichText = true`, and verify exact visible/bound document after both undo and redo, cleared history after an entry switch, and no mutation of the first document while undoing the second. The second replacement currently uses fresh `RichText.attributes`; carry the second entry's existing block attributes into that test edit as the proposal specifies, so block-identity loss introduced by the test does not obscure this binding failure. Verify another manager's completed notification cannot update the current binding; this protects a concrete cross-editor failure mode introduced by global observation. Re-run the existing image-arrival undo case with production rich-text configuration to cover the forced-refresh detail.

The parent reports that matching iOS isolation passes, but that log was not inspected in this review. Keeping iOS unchanged is appropriate unless native evidence demonstrates the same failure there. Hosted tests can establish document/history correctness, but cannot establish live Mac menu/shortcut interaction, VoiceOver, physical-device behavior or all attachment undo combinations. Actual implementation and relevant native evidence remain pending; no production source was changed by this review.

## Implementation and hosted native evidence review — 2026-09-21

**Accepted within the inspected source/hosted macOS scope; no remaining finding.** Inspected the implemented macOS coordinator, updated isolation fixture, production-rich-text image-arrival fixture, and `/tmp/journal-editor-isolation-mac-fixed3.log`. No tests were rerun. The log records all three selected tests passing: entry isolation in 0.074 seconds, image-only preservation in 0.006 seconds and image-arrival undo/redo in 0.011 seconds, ending with `TEST SUCCEEDED`.

The coordinator registers selector observers once for completed undo and redo. Its synchronous callback requires an editable current view, no active application pass, and exact identity with that view's UndoManager. It reuses document conversion, whose equality guard avoids publishing a duplicate bound edit, then explicitly forces image presentation refresh. Rendered state is updated before binding publication. This path introduces no new attributed-text render, selection reset or undo registration; the existing image-only refresh continues to preserve selection/typing state and suppress undo registration. Entry-switch history clearing and retained-formatting ownership checks remain intact.

The real native isolation fixture uses `isRichText = true` and exact original/edited documents. It verifies visible native restoration, bound Undo/Redo, cleared history after switching, rejection of a retained old formatting action, and preservation of the first entry when undoing the second. The unrelated-manager notification is posted while native text deliberately differs from the binding, so the unchanged-binding assertion meaningfully exercises identity filtering. Its saved native text is now an explicit immutable attributed-string copy, avoiding a live-storage reference. The second edit carries existing block attributes. Earlier fixture failures are not treated as current product failures.

The image regression now also enables production rich text. It verifies exact restored document, retained loaded attachment description/dimensions after Undo and successful Redo. Its edit precedes an image; it does not establish every replacement/deletion spanning an attachment. The broader Apple/hygiene runs were still pending and the reported iOS baseline was not inspected here. Interactive Mac menus/shortcuts, VoiceOver and live desktop behavior remain unverified; this approval is for the narrow binding correction and inspected native-state evidence, with no new layout or copy.
