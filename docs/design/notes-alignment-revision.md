# Notes alignment revision — 22 September 2026

Status: independently reviewed and implemented; bounded visual acceptance and remaining verification limits are recorded in notes-alignment-audit.md. Supersedes the source-fallback and Format Text command-picker decisions of the previous revision. User-supplied Notes screenshots are layout references; their private note contents are not fixtures or instructions.

## Evidence and scope

Read Apple's current HIG via developer.apple.com/tutorials/data/design/human-interface-guidelines/{sidebars,toolbars,onboarding,search-fields,keyboards}.json on 22 September 2026. Public guidance links: [sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), [onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding), [search](https://developer.apple.com/design/human-interface-guidelines/search-fields), [keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards). Sidebar guidance calls for room appropriate to the display and an intermediate content list for deep hierarchy. Toolbar guidance prioritizes standard components, deliberate small action sets and a trailing primary Done action. Search guidance prefers bottom placement when room allows. Onboarding should be brief and contextual. Standard text shortcuts and OS text services remain intact.

Keep macOS's existing three-column layout, neutral palette, native text behavior, dates at the top of entry rows, and established lifecycle/sync safety. Change only the requested issues and defects discovered by the audit. iPhone adopts an actual three-screen hierarchy; iPad uses the equivalent three-column split when space permits and the phone hierarchy in a narrow window. Native system materials adapt to the OS version; do not manually reproduce Liquid Glass or hard-code Notes yellow.

## Navigation and action placement

### iPhone

1. **Journals** root screen: large native title, All Entries above a Journals section; each journal row has book icon, name, live-entry count and disclosure. Templates, Archived, Recently Deleted and conditional Unavailable Journals form a secondary section. Top trailing actions: New Journal (folder.badge.plus), Settings (gearshape). No persistent Manage Journals button. Long-press journal offers Rename, Default Template (one submenu), Version History, Delete Journal. Names and counts grow with Dynamic Type. A native bottom search field searches all live entries; results carry journal labels. Compose at bottom trailing uses the last live journal or Default; with no live journals it opens New Journal first. It never silently chooses a deleted journal.
2. **Journal entries** screen: native Back to Journals, large journal name (or All Entries), optional concise count, compact rows grouped by month. Each row: secondary date, semibold single-line title, one secondary preview line. All Entries/search adds a small secondary book icon + journal name. No per-row independent card backgrounds beyond the platform grouped list. Context menu exposes entry actions. Bottom toolbar: native search field, template icon and compose icon. Search is scoped to that journal; All Entries stays global. Top More menu exposes journal actions, not application Settings. Template icon opens only search + template names in a lightweight anchored popover/adaptive compact presentation: selecting a name immediately creates an entry; no heading, preview, explanatory subtitle or Create step. Cancel by tapping outside/Escape. Normal compose respects the journal default template.
3. **Entry** screen: Back to entries, top trailing Share/export and More. While a title/body/table cell is editing, a trailing prominent checkmark with accessibility label **Done** appears. Done commits the current native composition, dismisses the keyboard, ends editing and preserves scroll; writing remains autosaved. Failed saves retain the draft and existing retry/export notice; Done must not imply sync completion. Back also ends input and follows existing save-before-switch rules. Tapping text resumes editing at the tapped position. New entry title still selects automatically.

A horizontal native input accessory above the software keyboard contains Formatting (Aa), Checklist, Table, Insert (links/images), Undo and Redo. No Find Format control or custom command search. Common hardware shortcuts remain in the native editor. While not editing, a small bottom toolbar offers the relevant writing actions and compose; no duplicate top formatting toolbar. Source/preview is a separate icon action, with dynamic accessible label **View Source** or **View Preview**, not inside Aa. It is reachable when viewing and editing without hiding Done or Back; use the bottom/accessory surface for the mode action on compact width. Accessory can scroll horizontally at large text; native touch targets remain44pt. A hardware keyboard does not remove the ability to finish editing.

Navigation route belongs to the UI, independently of the saved selected journal/entry. A fresh launch starts at Journals; persisted selection is a writing destination, not a reason to skip the hierarchy. Selecting a collection waits for pending save and only navigates on success. Back/swipe, switching journal, restoring/deleting current items, lock and rotation cannot leave an invisible stale editor or retarget captured formatting. Search state is scoped/reset on collection change. A failed save retains visible recovery controls and cannot silently navigate away from the draft.

### iPad

Regular width: Journals sidebar → entry list → detail with independent toolbar ownership. Sidebar collapse uses standard split navigation. Entry list owns search/compose/templates. Detail owns entry actions/source mode; formatting resides near input while software keyboard is active and remains discoverable with a hardware keyboard. Done ends editing in both cases. Popovers are anchored and appropriately sized; narrow Split View/Stage Manager uses the phone stack. Resize/rotation preserves journal/entry selection, draft, caret and scroll where native controls permit. No synthetic phone journal selector inside the entry list. Search follows system toolbar placement; no cramped three-column presentation in compact width.

### macOS

Preserve existing split proportions and editor. Sidebar toolbar gets New Journal icon next to collapse controls. Remove sidebar New Journal/Manage Journals text buttons. Settings is available via standard My Journal → Settings (Command-comma) plus a sidebar-owned gear if needed; remove gear from entry-list actions. All Entries row precedes Journals; global entries show journal indicator. Same compact date/title/one-preview rows. Default Template context menu has exactly one submenu with checked choices. Keep rename/delete/history in context menu.

Restore entry More in detail toolbar (latest user instruction supersedes earlier removal); same actions as row context menu, targeting the displayed entry. Source/preview gets a separate detail toolbar button labeled by destination mode, outside the formatting popover. Keep conventional Format menu keyboard shortcuts; remove Find Format and its shortcut everywhere. The template icon uses the same minimal immediate-selection popover, keyboard navigable search/names, without modal chrome. The empty Mac writing surface remains blank, eliminating the reported placeholder overlap without adding visual clutter. The iOS native placeholder derives from current text and disappears immediately on typing, with no competing SwiftUI overlay. Remove the source-fallback banner entirely.

## Setup and Settings

Replace the oversized grouped-form choice with a short, centered setup sheet: lock symbol; **Protect Your Journals**; plain paragraph **Encrypt your writing with a master password. You’ll need it to connect another device or restore a backup.**; primary **Use Encryption**; secondary **Continue Without Encryption**; small warning directly below **Without encryption, anyone with access to your files, server, or backups can read your journals.** Cancel uses normal sheet placement. No individual gray boxes around prose/buttons. Content-sized on Mac, scrollable on mobile/accessibility sizes. Choosing encryption reveals **Master Password**, one native new-password field, Show Password control, **Use at least 12 characters.** and short recovery warning; Back/Cancel/Create remain conventional. Passwordless selection directly creates the library. No generation button or confirmation field. Recovery/security behavior is unchanged.

Settings has peer sections Sync, Devices, Privacy, **Agent Access**. Move all existing grant/connection/revoke controls into Agent Access on Mac. iPhone/iPad Agent Access explains **Set up agent access in My Journal on your Mac.** without burying it under Privacy. Do not invent mobile server/agent execution. Retain permission scope/revocation controls. Remove redundant journal-management navigation while preserving accessible journal context/More actions.

## Markdown formatted experience

Markdown source is canonical (CommonMark + GFM supported by the pinned parser); source mode is explicit and never forced by inserting a table or pasting nested content. Native formatted representation must cover paragraphs/hard and soft breaks, all six headings, emphasis/strong/strike/code/link, nested and loose ordered/unordered/task lists, nested blockquotes, fenced/indented multiline code with language, thematic breaks, GFM tables with alignment, link references/autolinks and local images. Reference definitions remain preserved; editing a resolved link may normalize only that changed span. No gratuitous whole-document normalization on opening, mode switching or unrelated edits.

Implement native structured blocks for constructs a single flat native text view cannot represent portably, while retaining the established native editor for ordinary documents. Text leaves keep native spelling/correction, selection, dictation and accessibility. Tables display an actual grid with editable cells, header distinction, alignment and contextual add/remove row/column; Tab moves between cells, Return remains text input or advances according to native field semantics, and explicit row controls avoid accidental deletion. Code blocks use an inset monospaced surface with preserved whitespace and an optional language label. Lists preserve depth and numbering; quotes have a subtle leading rule. Inline images retain references/alt text and bounded dimensions. Remote images show a labeled placeholder rather than loading private URLs automatically. Raw HTML remains literal inert content; Markdown support is not permission to execute arbitrary HTML/scripts or fetch remote resources. Keep source as the complete escape hatch without imposing it on normal writing.

Every structural edit must participate in undo, preserve unaffected source and attachments, and pass through the existing draft/history/sync transaction. Table edits must not be reinterpreted as paragraphs or lost on selection change. Mode switches preserve native edit history or an equivalent coherent document undo chain. Copy/export should include human-readable formatted content with a lossless Markdown/portable route. Empty state is **Start writing…** only when the actual document body is empty; a table or code block is content. Do not cover text with banners, labels, or floating layout placeholders.

## Review amendments (binding decisions)

**Global creation.** All Entries, Journals root and global search compose shows a native journal menu when more than one live journal exists. Selecting a named journal creates there; with one journal it creates directly. With none it opens New Journal, then creates only after successful journal creation. Template creation in global scope first chooses a named journal, then opens template names; both IDs are captured and revalidated. Contextual journal lists compose directly into that visible journal. No invisible remembered destination in global scope.

**Template interaction.** Compact presentation has a native Close icon with accessibility label Close; normal content remains only search and names. Mac/iPad popovers support outside/Escape dismissal as well. Search focuses once on open. Up/Down chooses a result, Return activates only a selected live result, typing/highlighting never creates. Rows are44pt on touch; longer names wrap. Duplicate names show a short identifier only when needed. Empty copy: No Templates; no-match: No Results; creation error stays in place with the failed choice available to retry (existing specific save failure text where applicable). While pending disable activation and show a small progress indicator. Missing destination: This journal is no longer available. Missing template: This template is no longer available. Close remains available unless an atomic creation is being committed; cancellation must not cause a second creation. Templates collection remains reachable from Journals; Save as Template stays in entry More.

**Native editing/selection.** Prefer one native attributed-text document per entry, including nested indentation and code paragraphs, with tables as structured inline attachments with native editable cell controls. Ordinary text retains its existing native editor. The table is atomic when selected/copied across surrounding text; within its grid, selection is cell text. Copying the entire entry includes Markdown/plain-text representation of tables rather than an empty object character. Paste of Markdown into source uses exact source; a deliberate Paste and Match Style in formatted view inserts plain text; rich/structured paste preserves supported blocks. Do not introduce multiple independent undo histories: table/structural edits register with the entry's document undo coordinator, and native text undo is integrated in the same entry sequence. A source/preview change alone does not clear history. Table edit focus changes do not count as document edits. Toolbar commands target the captured body/cell selection; while title/search is focused, body formatting is disabled or explicitly focuses the body, never unexpectedly styles another field. Done unmarks composition before resigning responders; failures retain the in-memory draft.

**Tables.** Insert Table adds a2-column grid with header and one empty data row, without changing mode; focus enters the first header cell. Header-only tables are valid. Tab/Shift-Tab traverses cells in row-major order; at last cell Tab moves to the following paragraph (creating an empty paragraph only if necessary), and before first cell Shift-Tab moves to preceding paragraph. Return ends the current cell edit and advances to the next row in the same column; last-row Return exits after the table. It never silently creates a data row. GFM cells are single-line; pasted line breaks become spaces, literal pipes are escaped, and this is one undoable edit. A table context menu provides Add Row Above/Below, Add Column Before/After, alignment and Delete Row/Column/Table. Deleted cell content is recoverable through Undo. Focus after deletion goes to nearest surviving cell; deleting the final row/column removes the table and focuses the adjacent paragraph. No text is discarded by merely opening, switching view, changing focus or cancelling a menu.

**Lists and code.** Return continues the current list at the same depth; Return on an empty nested item outdents once, and at the outer level returns to Body. Tab/Shift-Tab indent/outdent selected list items, without taking native IME completion keys. Task checkboxes toggle explicitly and are accessible as checked/unchecked. Ordered starts and nesting/loose spacing are preserved. Code blocks render monospaced with whitespace intact; Return inserts a newline, Tab inserts indentation, Shift-Tab removes one indentation level. Down at the final line or an explicit Move After Code Block action exits to the following paragraph. Hardware and software editing menus expose indent/outdent and block exit where keys are unavailable.

**Back/save transition.** A single UI route coordinator owns stable journal/entry paths. Back, collection changes and route selection end composition, request the existing save task and change the route only on success. While awaiting, retain the displayed editor and disable repeated navigation; on failure keep the editor and retry/export controls. Do not present a success confirmation. Native swipe-back is available when there is no unsaved draft/failure; while a draft is pending, its gesture is disabled and the standard-looking Back control runs the guarded transition. Done dismisses input immediately and requests a flush; Back waits for that same flush if pressed next. A size-class transition retains route/model state and cannot discard a pending draft. An externally deleted/archived entry moves to the existing recovery view only after reconciliation, preserving a failed draft.

**Mode, keyboard and setup details.** View Source uses chevron.left.forwardslash.chevron.right; View Preview uses doc.richtext. Accessibility reports current mode and destination, and preview remains editable. Hardware/floating-keyboard iPad retains a bottom editing toolbar even when software accessory is absent; Done is tied to responder editing, not solely keyboard height. On older OS versions native bottom toolbar/search controls may use older system styling. Setup password warning: Save this password in your password manager. If you lose it and access to your devices, you won’t be able to restore your journals. Keep a backup, too. Cancel clears transient password; Back retains it; existing precise failure message and Create retry stay visible. At large text/keyboard the content scrolls while cancellation/primary actions remain reachable.

## iPad portrait overlay correction

At regular width with less than 1,000 points available to the split view, choosing a journal/collection dismisses the Journals overlay and reveals entries plus detail (`doubleColumn`). At wider widths preserve the person's existing column visibility. Measure the actual root view width, not device idiom or screen size, so windowed iPad layouts use the same rule. Selecting a journal must expose its entries without a second dismissal tap. No Mac change.

For regular iPad sidebar chrome, retain New Journal beside the native sidebar toggle. Place Settings as a normal Settings row with gear icon in its own final sidebar section; remove the additional top Settings button that causes toolbar overflow in the narrow sidebar. Compact iPhone continues to use the already-reviewed root toolbar. Copy remains Settings and New Journal. Use native list/button accessibility, Dynamic Type, and system surfaces; no custom footer or extra explanatory text. Existing empty/error/save-failure behavior remains. Verify portrait overlay selection, roomy landscape column retention, and Settings reachability.

## Contextual indentation controls

Complete the previously approved software access to list/code indentation in Aa. When the selection includes list items or a code block, expose Decrease Indent and Increase Indent in the scrollable formatting surface, adjacent to list styles. Use familiar decrease.indent/increase.indent icons with accessible labels, full 44-point targets on iOS and 30-point Mac targets. Hide these controls elsewhere and in source mode. A mixed task selection offers Mark as Complete unless all selected tasks are complete, then Mark as Incomplete. Neither action converts unrelated selected paragraphs, tables, code, or images. Existing keyboard shortcuts remain. No new persistent toolbar controls.

## Accessibility text navigation

Largest Dynamic Type inspection exposed unreadable journal labels in the regular iPad's narrow sidebar. At accessibility Dynamic Type sizes, use the existing full-width Journals → Entries → Entry navigation on iPad as well as iPhone. Do not cap the selected system font size. Preserve the active semantic route/draft when changing between stacked and split layouts.

At accessibility sizes, journal destination rows use a full-width, wrapping title with the entry count on a secondary line (1 entry / N entries). Omit decorative journal icons and disclosure chevrons in this layout so they cannot compress the name to zero width. The entire native row remains tappable and exposes its title/count and button role. Other collection rows show just their names. Standard text sizes retain the reviewed icon/name/count layout. Settings and New Journal follow the existing compact Journals toolbar; no duplicate Settings sidebar row. Empty/loading/offline/recovery states are unchanged. Verify phone and tablet at the largest setting, including Settings reachability, compose, template search, keyboard dismissal, and rotation without losing the active entry.

## Accessibility entry rows

At accessibility Dynamic Type sizes only, arrange each entry's metadata vertically: date first, then the full wrapping journal name in All Entries/Archived, without the decorative book icon. Permit the title to wrap to its full natural height; retain one preview line to keep the overview concise. A conflict retains its accessible Changes need review indicator beside the date. Normal-size rows and macOS retain the approved compact arrangement. Preserve full-row activation/context menus and one combined accessible label; this changes no empty/loading/offline/error behavior.
