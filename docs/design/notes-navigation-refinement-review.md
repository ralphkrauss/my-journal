Reviewed 2026-09-20 against `notes-navigation-refinement.md`, the delegated user requirements, current RootView and native editor selection/action handling. ## Verdict

**Direction approved; resolve the bounded details below before implementation.** A true three-column macOS split view with high-level sidebar navigation and an ordinary entry content list addresses the requested hierarchy directly. Removing the persistent date control, moving Change Date to contextual actions, and providing a visual native formatting popover reduce writing-surface clutter. The proposal correctly avoids copying unsupported Notes features. The remaining issues concern action placement and safe behavior, not a different visual direction.

## Required clarifications

1. **Specify the replacement locations for creation and iOS global actions.** “Separate creation options” and “offer accessible global navigation controls on iOS” are intentions rather than a reviewable layout. State the actual control/placement and contents for New Blank Entry/New Entry from Template, plus where Settings and Lock move when removed from Entry Actions. A native New Entry menu with a primary/default action or an explicitly described adjacent menu is appropriate; preserve straightforward New Entry and its keyboard command. Identify the iOS list-level global control and how it is reached from detail. Avoid duplicating global controls in both column toolbars or crowding the compact writing toolbar. Also specify whether the macOS sidebar's bottom New Journal/Manage Journals controls scroll or remain anchored and how they stay reachable in a short window. No new navigation concept is needed, but these placements are part of the user's explicit request.

2. **Preserve the unsaved-draft export escape path.** The blanket rule that every contextual action first saves and selects the row must have an explicit exception for Export Entry on the already-selected draft. It should export that captured draft even after saving fails, consistent with the existing recovery contract. A different row's action must still stop if the current draft cannot be saved; do not silently export the other row while abandoning the active draft. The toolbar's selected-entry Export action must retain the same safe unsaved export behavior. Read-only history/export may remain available for unsupported records; mutating actions must not become enabled simply because selection succeeded.

3. **Make Change Date's atomic patch and stale/failure state explicit.** Capture identity/date after the current draft has successfully settled; commit only the date against the latest supported, eligible record, preserving newer unrelated body/title fields and checking conflicts/lifecycle. Do not save the entire record captured when the sheet opened. An external date change must refuse the stale submission; any locally unsettled draft at final Save must remain preserved and block a stale overwrite. Use cross-platform copy **“This entry’s date changed. Close this sheet and try again.”** for that specific rejection; broader unsupported/deleted/conflicted states need their existing contextual explanation. Disable duplicate Save/cancellation during the owned commit, retain the proposed date on a genuine save failure with a meaningful retry, and reconcile a durable commit before lock or display refresh can invite a repeat. The date-only action should not regress the ownership patterns already reviewed elsewhere.

## Formatting and selection expectations

The B/I/U row, semantic style previews, native symbols and Link action form a restrained, useful popover. Do not show inaccurate selected-state indicators for mixed text. Bind a formatting session to the exact editable body identity and native selected range before presenting; opening or interacting with controls must not retarget a different entry, title, or stale body selection after replacement. Dismissal/paragraph selection should return focus predictably to that body. Link must retain the same captured body selection through its secondary prompt. Consecutive inline actions need to retain the updated selection/typing attributes rather than reapply an obsolete snapshot.

Give each button its full accessible label and keyboard focus, support Escape dismissal, and leave visual font styling supplementary to readable style names. Keep the controls scrollable at large text sizes with full labels and adequate targets. A native compact-width iOS adaptation is acceptable, but its actual layout must be inspected; a popover that adapts to a sheet still needs a clear way to dismiss and return to writing. Source declarations alone cannot establish VoiceOver or range preservation.

## Navigation, menus and scope

Use one active high-level destination and preserve the entry selection/draft when collapsing the sidebar. Collection changes must go through pending-save protection rather than setting selection state directly. The content title and search scope should remain understandable with the sidebar hidden; expose useful accessibility names for sidebar, entry list and editor. Entry list keyboard navigation and selected-row context-menu invocation must remain native. Test long journal names, narrow/short windows and the empty journal/collection states, not just the proposed default window size.

Captured row identity is the right context-menu invariant. Opening a menu should not save, mutate or switch selection; action execution must revalidate the captured target after any await, cancellation or lock. Recovery menus must preserve the existing explicit restoration route and should not add ordinary Delete/Move to unavailable content. Template menus should use template-specific deletion wording and omit actions that merely copy a template into another template unless that behavior is explicitly intended. No permanent-deletion action is approved by this proposal.

The Archive follow-up boundary is appropriate: encrypted archive export and recoverable Delete are not an Archive lifecycle. Record the requested reversible archive/Archived collection work explicitly and do not ship an inert or misleading menu item. This review approves deferral as a stated scope boundary, not a claim that the user's Archive request is fulfilled.
