## Proposal disposition

Approved for the bounded prefix-replacement correction, with the implementation/test requirements below. Choosing the first valid existing UUID within the same surviving text paragraph is appropriate when an untagged prefix precedes the original tagged suffix. It avoids inventing a new identity for the same surviving block and does not require mutating text storage, selection, composition, or the native undo stack. It is sufficient for the proposed attributed-text condition; final adequacy for the native failure requires the passing exact-document route.

Limit lookup to this text fragment's current paragraph content range. RichText.document already partitions valid image attachments from adjacent text before calling textDocument; preserve that partitioning and do not search neighboring paragraphs, image blocks, or beyond the current range. Exclude paragraph terminators from fallback where present so identity is taken from surviving content. Missing attributes, non-string values, and malformed UUID strings should be skipped without changing content. An empty/no-valid-ID fragment retains the existing fresh-ID behavior.

Preserve first-valid-ID precedence, including when several IDs coexist after a join or attributed paste. First choose the candidate, then apply existing duplicate normalization. Do not reinterpret “valid” as “not already seen” and choose a later ID to evade a duplicate: that would silently change split/join ownership policy. Keeping the first paragraph's valid leading ID authoritative matches the existing behavior. A later duplicate receives a new ID through the current normalization path.

## Meaningful verification and limits

The appearance test currently only asserts `edited != original` before retaining the edited document. That can miss a one-time identity change during the initial replacement. Add an explicit assertion that this edited block keeps the original target block's ID (and expected replacement text), while retaining exact original/edited document equality across undo/redo. Do not weaken equality to text-only to make the test pass.

A small deterministic attributed-text regression is warranted because the native route alone does not establish range isolation. Cover an untagged or malformed-ID prefix with a valid suffix in the same paragraph, retain first valid leading-ID precedence when another ID follows, and show that an ID belonging only to a following paragraph or adjacent image is not borrowed. Assert preserved content and unique block identity where splitting creates duplicates; avoid expecting a particular newly generated UUID. These are behavioral boundaries, not getters or internal-call tests. Existing focused rich-text/image boundary tests may supply some of this evidence rather than duplicating cases.

This is not a universal stable-ID solution. Replacing all tagged content, creating empty/new paragraphs, splitting one tagged block into multiple blocks, and joining/pasting content carrying different IDs can still require fresh or normalized identities under current policy. UUID syntax is not evidence of provenance; same-paragraph fallback is a deterministic preservation policy, not proof that any surviving imported attribute belongs to the original block. No new content deletion or formatting policy should be introduced in this correction, and paragraph kind still follows the current leading attributes. The passing native prefix route will not prove stable identity for all those cases or real marked-text composition.

No production files were edited and no reviewer tests were run. Implementation and the failing native route remain unverified at this proposal stage. Existing packages predate any forthcoming production correction and must retain that scope.
