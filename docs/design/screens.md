# Native interface proposal — revision 1

## Main window and navigation
macOS 13+: native NavigationSplitView, 260-point preferred resizable sidebar (220 minimum), 900×650 default window, 640×420 minimum. Sidebar holds journal Menu (selected name, journal names, New Journal…, Rename Journal…), selected-journal search, and a reverse chronological list grouped by month. Rows have date, explicit title or first nonempty body line, and a two-line preview. Empty titles never render 'Untitled'. Completely empty entries show 'New Entry'. New entries are durable drafts; we never discard them automatically. Journal date is editable and controls sorting; creation/modification timestamps are separate.
Toolbar: sidebar toggle, New Entry (⌘N), style menu (Aa), Insert Image…, and More. Controls remain available with sidebar hidden. View > Show Sidebar and ⌘F reveal it. Journal switching is also in the File menu. Sidebar selection survives collapse. Search scope is the selected journal; placeholder 'Search [journal name]'. No global scope in initial UI; switching journals changes search scope visibly.
iOS: journal/entry list pushes the same document into a full-screen editor; standard back navigation. Toolbar contains New Entry, Aa, Insert, More without custom floating controls. Dynamic Type and safe areas respected. Both clients share models, storage and sync.

## Editor
Readable column up to 720 points, left-aligned text with 24-point minimum side padding. Date above optional title. Title placeholder 'Title'; body placeholder 'Start writing…', removed on typing. Semantic body font at preferred size; macOS View > Make Text Bigger/Smaller affects display, not document content. No word count, streaks or dashboard. System light/dark and accent behavior, system background/label/separator colors. Do not override text-system correction preferences.
Style popover/menu: Body, Heading, Subheading; Bold ⌘B, Italic ⌘I, Underline ⌘U; Bulleted List, Numbered List; Link… ⌘K. Native Format menu and native text contextual menus. Actions apply to selected text/current paragraph, preserve selection, and participate in undo. Images insert at cursor via picker, paste or drop; fit available width, preserve original bytes, selection/removal supported. Image details allow 'Description' for accessibility; arbitrary layout/drag resizing deferred. Missing image retains position and description with 'Image unavailable' and retry if remote.
Unknown document versions/content open read-only with 'Update Journal to edit this entry.' Export remains possible. Content is never silently flattened.

## Creation, journals and templates
New Entry uses current journal's optional default template; a menu offers Blank Entry and New Entry from Template…. Focus body after creation. Built-ins: Daily Reflection, Gratitude, Workday Log, Weekly Reflection (removed 2026-10-04: new libraries start without templates; see no-built-in-templates-2026-10-04.md). Template questions are editable headings; no required answers or completion state. Template editor uses same rich editor. Save as Template… copies entry content; template changes affect future entries only. Applying a template to an existing entry is unavailable initially.
Manage Journals allows New, Rename, default template, and Delete. Deleting a journal moves its entries to Recently Deleted; explain count in confirmation. Move Entry… flushes current editing before changing journal. Recently Deleted offers Restore and Delete Permanently… with explicit irreversible confirmation. No automatic purge initially.

## Saving, sync and conflicts
Local save debounced briefly with flush on selection/scene change, no success banner. Normal sync is quiet. Pending state after a short delay uses cloud indicator with accessible label and details 'Saved on this Mac. Waiting to sync.' (iPhone equivalent). Offline does not block editor. Error details 'Couldn’t sync. Your changes are saved on this Mac.' + Try Again. Actual local save failure retains in-memory text and presents 'Couldn’t save changes.' + Copy Text / Export Entry / Try Again; never falsely claim durable save.
Conflict notice 'This entry has changes from another device.' + Review Changes. Sheet presents both versions with modification times/device labels, full content, and Keep Both (default), Keep This Version…, Use Other Version…. Choosing one requires confirmation; originals are kept in recoverable conflict history. Resolution checks current remote revision and repeats review if changed. Sync never steals editor focus or replaces active unsaved text.

## Getting started and security
Welcome: 'Journal', 'A space for your thoughts.' Actions 'Start a Journal' and 'Connect to a Server…'. Supporting copy 'Write on this device. You can set up sync later.' No account required for local start. On Mac local backend is optional under Settings > Sync > Set Up on This Mac; enabling network access is distinct, initially loopback only.
Connect: Server Address field, Continue; verified server state routes to initial setup (Setup Code), existing-device approval, or Recover Journals. Existing local journals must be preserved and explicitly uploaded/merged only after consent. Recovery setup displays generated high-entropy passphrase and Copy / Save Recovery Key…; confirm saved and re-enter requested words. Copy: 'Keep this somewhere safe. You’ll need it if you lose access to your devices.' App lock is separate: Settings > Privacy, Lock Journal, PIN setup, biometric toggle when available; explain PIN unlocks only this device. Auto-lock on background (iOS), session lock or configurable inactivity (Mac). Locked UI shows no previews, search results or agent access.
Pair: requesting device shows a short expiring code; authorized device in Devices > Add Device enters it, sees new device name and confirms. Encryption key is transferred encrypted to requesting device, never plaintext via server. Recovery alternative requires server address and recovery passphrase. Devices list shows current device and Revoke…; explain already downloaded content cannot be erased remotely.

## Agent access
Settings > Agent Access defaults off. Add Access… requires a name and checked journals (none preselected). Read-only only. Copy Connection Instructions gives local MCP configuration and accessible scope; explicitly say a cloud agent may send retrieved text to its provider. Revoke removes grant immediately. Access requires app unlocked. Activity lists time, grant and action without duplicating journal text. No network-public plaintext endpoint.

## States, accessibility and copy
Empty list: 'No Entries', New Entry. No selection: 'Select an Entry'. Search empty: 'No Results', Clear Search. Loading displays cached content and labels operation. Restore: 'Restoring Journals…', progress and retry. Native sheets use Cancel and specific action names. Icon controls have labels/help. Lists expose date/title/current journal; editor exposes headings and image descriptions. Native focus rings, full menu/keyboard equivalents, no hover-only actions, no color-only states, no fixed-height clipping with enlarged text. Verify dark/light, contrast, transparency, motion settings and long content. Errors must state what remains safe and next action without implementation jargon.

## Revision 2 — resolved review findings
- Failed local save pins the editor draft and prevents selection changes, journal moves, and destructive actions until save succeeds or a complete lossless entry export is written. Native close interception offers Keep Open and Export Entry…; no dismiss-and-discard action. Lock hides the draft without dropping it; unlocking returns to the same draft and error. iOS background retains memory and retries persistence; the UI cannot promise durability if the OS terminates after a real storage failure.
- Journal deletion is a recoverable journal tombstone with its name and default template intact. Confirmation: 'Delete “[name]”?' / '[count] entries will move to Recently Deleted.' Restore Journal restores the journal and entries that were deleted with it, not entries independently deleted beforehand. Individually restoring an entry from a deleted journal offers 'Restore “[journal]” and Entry'. Permanent deletion has a separate irreversible confirmation.
- Conflict review is a scrollable sheet; at narrow widths a segmented Local/Other-device selector changes the full preview, preserving scroll position per version. Each version is labeled device plus modification time. Actions: Keep Both ('Both versions will remain as separate entries.'), Keep Version from [device/time]…; identical names always include timestamp. More > Version History opens retained original snapshots with Restore as New Entry. Remote changes during review display 'Another version is available. Review it before continuing.' without moving keyboard focus or losing the local draft.
- Invalid connection: 'Enter a valid HTTPS server address.' (loopback HTTP allowed for bundled/local development). Unreachable: 'Couldn’t connect to the server.' / 'Check the address and your network connection.' / Try Again. Invalid setup code: 'That setup code isn’t correct.' / Try Again. Unauthorized: 'This device no longer has access.' / Connect Again. Expired pairing: 'This pairing code has expired.' / Get New Code. Canceled pairing: 'Pairing was canceled.' / Try Again. Address and journals remain intact. Approval shows code AND device name with 'Confirm this code matches the new device.' / Add Device. Cancel returns without granting access.
- Connecting with existing local content: explicit 'Upload Local Journals' confirmation ('Your local journals will be added to this server. Existing journals will be kept.'). Cancel leaves local mode untouched. There is no implicit account switch or destructive replacement. Existing records are re-encrypted for the target vault only after successful authorization and consent; attachment transfer precedes entry sync.
- Use 'Recovery Key' consistently for the generated high-entropy word/string secret. Setup: 'Keep this somewhere safe. If you lose access to all your devices and this recovery key, you won’t be able to recover your journals.' Also: 'Your recovery key is not a backup. You also need your server data or an exported archive.' Incorrect: 'That recovery key couldn’t unlock your journals.' / Try Again. A local-only journal uses its local encrypted recovery envelope; portable archive includes the envelope, never the plaintext key.
- App lock is opt-in; PIN is required when enabled, biometrics an optional convenience. 'This PIN unlocks Journal on this device. It cannot recover your journals.' Forgotten PIN offers Unlock with Recovery Key; validates by decrypting the locally stored wrapped journal key, then allows setting a new PIN without deleting local data. If both PIN and recovery key are lost, an already authorized biometric unlock remains available. Do not offer a misleading destructive reset to solve this. PIN verifier is salted and stretched; throttle repeated failures; OS Keychain protects journal keys at rest.
- Agent grant final sheet: '[agent name] can read entries in the selected journals while Journal is unlocked. A cloud agent may send this content to its provider. Revoking access stops future reads but cannot retract content already read.' Final action 'Allow Read Access', disabled for empty selection. Revoke invalidates subsequent reads immediately. Connection instructions use a local authenticated bridge; tokens must not be copied into public logs.
