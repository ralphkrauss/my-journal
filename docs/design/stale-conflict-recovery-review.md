## Independent proposal review — 2026-09-21

Read `stale-conflict-recovery.md` and the current `EntryConflictReview.swift`; inspected the pre-fix screenshot `artifacts/stale-conflict-before/1DFEEA06-FB43-48ED-9237-3ABF0E8D330B.png`. The screenshot shows unchanged local preview and resolution controls with the generic “This entry has changes from another device.” message below them. This does not explain that the attempted choice was rejected or that a fresh review is needed. No reviewer test rerun was performed.

The proposed refresh-without-replaying-resolution is appropriate. The copy is concise, keeps the action clear, and avoids claiming a resolution succeeded. Hiding stale previews and destructive/resolution controls after reload failure is safer than leaving an apparently actionable old comparison. Native Try Again and Cancel remain familiar. System text wrapping, secondary information color, existing version selector, and the largest-size menu are consistent with the established interface.

**One material presentation detail needs explicit revision before implementation:** a stale choice is commonly made near the bottom of this long sheet. Inserting “These changes were updated. Review both versions again.” above the selector does not ensure the user sees it if the scroll offset remains near the old actions. On successful refresh, bring the notice and reset selector into view, including at accessibility sizes. Use a stable scroll target with reduced-motion-aware behavior; provide an appropriate accessibility announcement or focus transition so VoiceOver users learn that the comparison changed. On refresh failure, ensure the new failure/retry state is visible as well. Do not move focus merely for unrelated model refreshes, and never replay the original resolution.

Implementation must distinguish a storage stale-conflict rejection from ordinary save failures. Clear the pending confirmation immediately upon stale rejection and on version changes; keep the unavailable-preview state authoritative until refresh succeeds. Retry must refresh only. Guard all postawait success and error publication with the captured store/session, including after pending-save completion and image/preview work where relevant. The parent additionally proposes capturing session/cancellation/replacement inside `AppModel.refresh`; this addresses the fact that caller-only checks occur too late to prevent refresh's own stale snapshot publication. That source change needs review alongside the view, including its later awaits.

The draft-preservation rule is sound provided it compares against a captured existing stored item, checks selected identity, and rechecks after the await. A nil or missing old stored item is not evidence that a current draft may be replaced. Ordinary unsaved draft edits must survive reload; a successful refresh should not silently reset selection elsewhere. Avoid extending the commit/reload path's existing draft-clearing behavior into this noncommitting stale-refresh path.

Requested evidence should show the notice and new remote contents after the stale rejection, before any new resolution, at normal and largest text sizes. Store assertions must separately establish no history or version mutation from the rejected operation, then the later explicitly chosen result. Loading, retry failure, changed-type routing, already-resolved state, VoiceOver and adversarial session timing remain unverified unless actually exercised.

**Outcome: direction accepted; revise the visibility/accessibility transition before implementation approval.** No production files changed. Source implementation and actual UI inspection remain required after proposal approval.

## Initial implementation source review — 2026-09-21

Inspected updated `EntryConflictReview`, shared `AppModel.refresh`, routing, sheet scroll structure and draft reconciliation. The view now distinguishes stale conflict rejection, clears pending confirmation, hides old content/images while refresh is unavailable, and makes Try Again refresh only. Its successful stale reload uses the required nonnil prior stored item / same selection / postawait draft equality checks. Store/session/cancellation checks protect resolution completion and error handling; the status scroll and accessibility-focus binding follow the approved explicit-completion design.

**Material shared-refresh regression:** the new unconditional `!replacingVault` entry/postawait guards silently skip legitimate existing postcommit refreshes inside `installServerVault` and `installArchive`, whose `replacingVault = true` scopes remain active until their defers run. Those callers clear items then call refresh/selectInitialEntry; returning early can leave a successfully installed vault displaying no journals. Preserve a legitimate refresh begun in the captured replacement phase while rejecting phase/session changes, or provide an explicit internal postcommit path. This must be corrected before source approval. Session checks remain necessary; caller-only checks cannot undo an already published stale snapshot.

Two bounded completion details also need correction. First, when explicit refresh discovers the conflict is already resolved, `error` becomes nil and `reviewStatus` has no target, yet `refreshGeneration` still asks to scroll/focus `review-status`. Attach that stable target/focus to the resolved message too, so the user is brought to the completed state. Second, revalidate inside each scheduled task before calling pending-save/refresh helpers: validation before creating `Task` does not prevent a queued task from starting after session invalidation. This particularly matters for committed reload, whose helper clears draft/selection before its first await. A single entry guard in both task closures, plus a defensive helper-entry guard where appropriate, is sufficient without redesigning the operation.

No actual corrected screenshots, completed Apple logs or reviewer reruns inspected in this pass. No production edits. Source approval remains pending these corrections; image/loading/failure and VoiceOver behavior require their separately bounded evidence.
