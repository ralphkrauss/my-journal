# Native writing and onboarding revision

2026-09-21. Requested changes take priority over distribution work. Existing user journals and the running Journal Test remain untouched.

## References and decisions

- Apple Notes [Add links](https://support.apple.com/en-gb/guide/notes/apde615d29c2/mac): selected text → Command-K, URL entry, native editing/context menus. Our insert sheet additionally exposes Text when no selection exists, rather than inserting a bare URL without choice. Selected text is prefilled and editable; Cancel restores the captured insertion point. Invalid destinations remain in the sheet with “Enter a valid web or email address.” Only http, https and mailto are supported.
- Apple Pages [Use templates](https://support.apple.com/guide/pages/use-templates-tan5c52a733c/mac): explicit template chooser and a preferred template for normal creation. Use New Entry for the journal default; an adjacent labeled “Templates…” action (doc.on.doc) opens a chooser with Blank Entry and named templates. File > New Entry from Template… provides keyboard/menu access. No isolated chevron and no nested creation menus.
- Apple [Password AutoFill](https://developer.apple.com/documentation/security/enabling-password-autofill-on-a-text-input-view): native secure input with newPassword on creation and password on recovery, paste permitted, system keyboard, no custom keyboard. Generator availability depends on OS/password provider and associated domains; do not promise automatic suggestions for arbitrary self-hosted domains. Provide a Generate Password action as a local fallback, reveal toggle, and Copy Password. Never log or persist the password. Generated passwords use cryptographic randomness.
- The user's Notes screenshot defines the compact formatting presentation. Retain supported portable features; do not add unsupported styling for visual similarity.

## Onboarding and protection

“Start a Journal” opens “Create Your Journal”. One “Master Password” field, “Show Password”, optional “Generate Password” and “Copy Password”, and “Encrypt Journals” enabled by default. Explanation: “Use this password to recover your journals or connect another device. Save it in your password manager.” Minimum 12 characters, no character-composition rules, no confirmation entry. Preserve exact password bytes, including spaces. Cancel returns to welcome, Create is disabled while invalid/busy; failure stays on the form with entered data, success clears it and opens Default. No generated recovery-key confirmation screen for new journals.

When encryption is off, label the same field “Access Password”. Warning under the switch: “Entries, images, and backups won’t be encrypted. Anyone with access to the files or server can read them.” Additional explanation: “Your password still protects server access.” Existing vaults keep their current protection; this is a new-vault choice, not a risky in-place conversion switch. Privacy displays the vault’s protection state and explains that a new journal library is needed to change it.

Keep random 32-byte vault key wrapped using PBKDF2-HMAC-SHA256 (600,000 rounds) and AES-GCM. Recovery-envelope version 1 remains legacy trimmed recovery phrases. Version 2 is exact user-password encrypted content; version 3 is exact user-password plaintext content. Version determines content protection consistently for local records, history, conflicts, attachments, sync, pairing and archive restoration; unknown versions fail closed. Do not expose the access/recovery authentication secret via the plaintext content. Plain records are base64 JSON in existing transport/storage fields, images raw bytes. Archive inventory remains authenticated using the wrapped secret, but content in unencrypted archives is readable. No claim of tamper protection for plaintext records. Server authentication, scope restrictions and transport requirements remain in force. Server must persist/return the envelope version; old servers must reject new versions rather than silently normalize them.

## Mac layout

Native three columns: journals sidebar, inline entry list, editor. Entry column owns a compact header/footer action strip containing New Entry and Templates…; this deliberately avoids SwiftUI merging list/editor toolbar items at narrow widths. Editor toolbar only Formatting and Insert Image plus actionable sync status. At minimum window width, labels may use native symbol tooltips but cannot overlap another column. Entry rows use a one-line title and two-line whitespace-normalized snippet with intrinsic height and native truncation; no fixed-height cards.

New entry focuses and selects the title once, including a template-derived title. Return moves into the body. Restoring/opening an existing entry never steals focus. Keep template content intact; retire automatic template body focus for newly created entries.

Entry context menu owns Change Date, Move, Archive, Save as Template, Version History, Image Descriptions when applicable, Export and Delete. No duplicate Mac ellipsis. Journal context menu owns Rename…, Default Template submenu with selection checkmark, Version History and Delete Journal… (existing data-loss-safe deletion sheet). Conflict-blocked edits remain disabled and review remains reachable. Rename uses one prefilled field, Cancel/Rename. No action should implicitly edit another selected journal.

## Formatting and links

Mac popover approximately 230 points wide, 28–32 point full-width rows, 8-point outer inset. Bold/Italic/Underline across top, divider, Heading/Subheading/Body, divider, lists, divider, Link…. Entire row is a rectangular hit target; hovered/selected states use system colors. Current paragraph and inline state reflected accessibly; mixed selection must not falsely claim a single state. Style changes retain the captured entry/selection session, respect undo and focus. The toolbar button toggles the popover on repeated clicks without pointer movement; use a native presentation bridge if SwiftUI dismissal consumes the activating click. Escape/outside click dismiss. Touch uses at least 44-point targets and supports large Dynamic Type; no fixed popover height that clips content.

Link sheet: “Add Link”, “Text”, “Link”, Cancel/Add Link. Prefill Text from selection; when empty it is optional and falls back to URL. Preserve existing selected character formatting when only adding link attributes. Validate before dismissal; do not silently ignore invalid input. Cancel and accept return to the original editor only if its captured session remains valid. Lock/navigation cancels without editing another entry.

## Settings and journals

Mac uses only the standard Settings window, accessible by Journal > Settings… and Command-comma. Sidebar Settings… opens the same window (compatibility action on macOS 13). No sheet containing a nested tab-window. Settings window: native tab selector with Sync, Devices, Privacy; plain full-size pane content, no custom shadows/background box/padding around a second panel; normal window close, no Done. Size resizable enough for forms; pane contents scroll.

Manage Journals opens a separate sheet titled “Journals”, with native close/Done. Journal editing uses a single native labeled Picker for Default Template, no wrapper Menu/custom chevrons. Bindings read/write latest model record and show the selected template immediately, preserving unrelated journal fields. Errors remain visible and restore the persisted selection.

On iPhone/iPad, a distinct Settings gear in the entry-list navigation toolbar opens a Settings navigation list (Sync, Devices, Privacy, Journals), with pushed panes and Done at the root. Manage Journals goes directly to its own sheet. Journal picker also offers per-journal management actions without pretending right-click is required. Entry actions remain in a detail ellipsis on touch and context menus on entry rows. Creation remains on the entry list. Formatting becomes adaptive popover/sheet with touch targets, link sheet uses native keyboard-safe scrolling. All platforms use neutral semantic colors, native typography and focus, system appearance/contrast/motion, readable labels and accessible controls.

## Acceptance boundaries

Meaningful checks: legacy recovery unchanged; exact master-password round trip/wrong password; encrypted vs plaintext records/images/archive restore/reopen; sync/pairing protection consistency; selected/no-selection link insertion with undo and stale session; fresh title focus; persistent default-template update without overwriting a renamed journal. Inspect Mac narrow/default windows, actual repeated formatting-button clicks and row hitboxes, long list snippets, Settings access. Inspect iPhone and iPad including large text. Preserve the existing conflict, recovery, authorization and useful-test policies. Produce a separate local review build without resetting existing data.

## Review amendments

Credential copy follows the envelope: version 1 uses “Recovery Key”; version 2 “Master Password”; version 3 “Access Password”. Before reading an archive/server envelope use “Password or Recovery Key”. Incorrect credential: “That password or recovery key isn’t correct. Try again.” Unlock, local-server setup, server connection and archive restore all follow this rule. Legacy key display/export/confirmation is retained only for old unconfirmed vaults; new vaults have no Save Recovery Key step. Backup copy is conditional: encrypted → “An encrypted copy of your journals, including images and earlier versions. Keep your master password separately.” Legacy substitutes “recovery key”. Plaintext → “Includes readable entries, images, and earlier versions. Keep the archive private. Your access password is needed to restore it in My Journal.” Pairing must show “Encryption is off for this server. Anyone with access to its files can read your journals.” before approving a plaintext import/upload.

Password creation always shows “Use at least 12 characters.” and “If you forget this password and lose access to your devices, you won’t be able to restore your journals.” For plaintext clarify that readable content can still be recovered directly from files. Reveal changes visibility without losing input or disabling paste/AutoFill semantics. Generate replaces the field only when empty; if already populated the action is “Replace with Generated Password…” with explicit confirmation. Copy is enabled only for nonempty input and temporarily reads “Copied”; it never copies automatically or clears unrelated clipboard contents. Password-manager saving is the user’s choice. Busy creation disables dismissal/changes and shows “Creating…”; failure leaves all values available for retry. Cancel clears transient password and returns to welcome, never creating storage.

Template chooser is a sheet titled “New Entry”, with one native list: Blank Entry, then available named templates with a two-line content preview. Single selection, Cancel/Create toolbar actions, Create disabled without selection/busy. Blank is initially selected, so keyboard Return can immediately create it. No new entry is saved until Create. The current journal name is shown as the destination; if it changes or becomes unavailable while the sheet is open, creation stops with an explanation. Empty template list still offers Blank Entry and “Save an entry as a template to use it here.” Errors keep the chooser open. iPhone uses a NavigationStack sheet with scrolling and native Done/Cancel actions; regular-width iPad uses a bounded sheet with the same semantics. Both list creation actions remain in the entries screen, not the detail editor. On compact iPhone, the journal selector includes “Manage This Journal…” opening journal details (rename/default/delete), “Manage Journals…” and collections. On regular iPad, use the same journal selector/context menu and entries/detail split without squeezing a third column into portrait. Settings uses pushed navigation on iOS/iPad, with Back from a pane and Done only at its root. Touch entry detail retains ellipsis because right-click is not a discoverable primary interaction there.

Final interaction clarifications: Generate Password and Copy Password are always offered (Copy disabled while empty). Password starts hidden and focused. Creation error fallback is “Couldn’t create your journal. Try again.” with actionable storage errors retained where available. Unknown format: “Update My Journal to open these journals.” No editing or import follows an unknown format. Template chooser uses Cancel/Create on every platform, including iPhone. Formatting uses an anchored popover on macOS and regular-width iPad; compact iPhone uses a scrolling sheet with Done and no fixed content height. Mac app menu reads My Journal > Settings…; project display name is My Journal.

## Implementation research and refinements

Apple Pages [link editing guide](https://support.apple.com/en-gb/guide/pages/tand51db403/mac), checked 2026-09-21, explicitly separates Display and Link fields. This corroborates our Text/Link sheet and editable selection label. iPhone formatting uses medium/large native sheet detents; the list scrolls at large text. Regular iPad keeps its anchored popover. The current journal is already named in its selector, so omit a duplicate iOS navigation title that competes with toolbar buttons in an iPad sidebar.

Recovery format 2/3 now binds the format version in AES-GCM wrapped-key AAD (`journal:v{version}:recovery`). Pairing includes the recovery version inside its authenticated encrypted grant and refuses a mismatching server envelope. This prevents a server response from silently downgrading the encryption choice.
