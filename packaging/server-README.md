# My Journal server

This folder includes its .NET runtime. Keep the entire folder together. No .NET installation is required.

Run `./journal-server` to start on `http://127.0.0.1:8080`. The default data directory is `~/Library/Application Support/Journal Server` on macOS, and `$XDG_DATA_HOME/journal-server` (or `~/.local/share/journal-server`) on Linux. The one-time `setup-code` file is inside that directory. Enter it in My Journal when you connect to the server for the first time (Settings > Sync > Connect to a Server…). Do not share the code or data directory.

Set `Journal__DataDirectory` (or pass `--Journal:DataDirectory=<directory>`) to use a different directory and `ASPNETCORE_URLS` to change the listening address. The `--backup`, `--restore` and `--recovery-code` commands read the same settings and options as the server. Keep HTTP on loopback; use a private HTTPS connection such as Tailscale Serve, or an HTTPS reverse proxy, for other devices. Single owner, one process, local persistent filesystem; do not run multiple replicas over the same SQLite data.

On loopback the server accepts only the host names `localhost`, `127.0.0.1`, `[::1]` and `*.ts.net`, so Tailscale Serve works as is. An HTTPS reverse proxy that forwards its own host name needs that name in `AllowedHosts`, separated by `;` and including the defaults you still use, for example `AllowedHosts="localhost;127.0.0.1;[::1];journal.example.com"`. Otherwise its requests get 400. To rate-limit each client separately instead of everyone behind the proxy together, set `Journal__TrustedProxies` to the proxy's address, for example `127.0.0.1`. Anyone who can reach the server can try to guess your master password through it, slowed down after 20 wrong attempts an hour, and anyone with its data or a backup can guess offline; prefer a private network, and use a strong password.

The server runs until stopped with Control-C. Running it as a system service is optional; the macOS app can manage its bundled server itself. Other devices can sync only while this server is running and reachable. Devices authenticate independently of network location.

For a consistent backup, run `./journal-server --backup /path/to/new-backup`. Records of encrypted libraries stay encrypted in the backup; libraries created without encryption are backed up readable, so keep backups private. To restore, stop the server, point `Journal__DataDirectory` to a new empty location, and run `./journal-server --restore /path/to/backup`. Preserve the original until recovery is verified. Keep the master password or recovery key separately. Restoring signs out every device, because the backup may include access you revoked later: reconnect each device you still use with Settings > Devices > Connect Again… and your master password or recovery key (for a library without a password, run `./journal-server --recovery-code` once per device). The restored server gets a new identity, so reconnected devices send back any changes the backup is missing instead of losing them; differing edits appear for review. Never copy only a live SQLite database without its write-ahead log.

Back up before upgrading. Replace this program folder without deleting the data directory. Before it migrates an existing database, the server copies it to `journal.pre-migration.db` in the data directory. It refuses to start on a database written by a newer version and leaves it unchanged; install that version or later rather than downgrading.

Check this package against the SHA-256 checksum published with its release. See the project's security and self-hosting documentation before using it for journals you care about.
