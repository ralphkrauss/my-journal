# Agent access through MCP, version 2

Capability `agent-access-2` (in `/v1/server` and `/v1/status` `features`; version 1, `agent-access`, approved by a typed 8-character code and is no longer served). The sync server is a remote [Model Context Protocol](https://modelcontextprotocol.io/specification/2026-07-28/) server: any MCP client connects to its MCP endpoint, authorizes with standard MCP authorization (OAuth 2.1), and reads the journals the owner allowed, read-only. The client's request appears on the owner's devices; the owner approves it by entering the two-digit number the client's authorization page shows. Design, rationale and reviews: [docs/design/agent-access-server.md](../docs/design/agent-access-server.md) and [docs/design/agent-access-simplified.md](../docs/design/agent-access-simplified.md).

## Addresses

- **MCP endpoint** `{origin}/mcp`, the canonical resource URI (RFC 8707, RFC 9728). **Issuer** `{origin}`.
- `{origin}`: `Journal:PublicUrl` when set (must be `https://host[:port]`, or `http://` with a loopback host; the server doesn't start otherwise), else `JOURNAL_URL` when it is such an origin, else the request's host with `https` when TLS ended at the server, at a trusted proxy (`X-Forwarded-Proto` from `Journal:TrustedProxies`) or at Tailscale Serve (loopback connection, `*.ts.net` host), and `http` only for loopback hosts. With a configured origin, MCP, metadata and OAuth requests for another host are refused.
- `/v1/server` and `/v1/status` return `mcpUrl`, or `null` with `mcpUnavailable`: `https-required` (plain HTTP from another computer) or `public-url-required` (listening beyond loopback without a configured origin or `AllowedHosts`).

## Transport (Streamable HTTP)

The endpoint implements revision **2026-07-28** (stateless, per-request `_meta`) and, for clients that still use the handshake, **2025-11-25** and **2025-06-18**.

- `POST` only; `GET`, `DELETE`, `PUT`, `PATCH` → `405` (`Allow: POST, OPTIONS`). Responses are `application/json`; no SSE, sessions or resumption (`Mcp-Session-Id`, `Last-Event-ID` ignored). `Accept` must admit `application/json` (missing means `*/*`), else `406`. One message per request, ≤ 64 KiB; arrays → `400` `-32600`; unparsable → `400` `-32700`. Notifications → `202`.
- A valid access token is required on every request, checked before the body is read. Without one: `401` with `WWW-Authenticate: Bearer resource_metadata="{origin}/.well-known/oauth-protected-resource/mcp", scope="journals:read"` (plus `error="invalid_token"` when one was presented); a token without the scope: `403` `error="insufficient_scope"`.
- `Origin`: a request with a valid token is served from any origin. Without one, an absent `Origin`, the public origin, `Journal:McpAllowedOrigins`, any well-formed `https` origin and loopback `http` origins get the `401` challenge with CORS headers, so browser clients can start authorization; the literal `null` origin and other `http` origins get `403` without CORS or a challenge. A challenge reveals nothing and a DNS-rebinding page can't hold a token; with a configured public address, requests for another `Host` are refused before this (`400`). Preflights are answered for any origin; responses echo the origin (no credentials), reflect requested headers and expose `WWW-Authenticate`.
- **Era.** A `params._meta["io.modelcontextprotocol/protocolVersion"]` decides: `2026-07-28` modern, `2025-11-25`/`2025-06-18` legacy semantics, anything else `400` `-32022`. Without it: a header naming 2026-07-28 or later → `400` `-32602`; `initialize` or a legacy header → legacy; no header → `400` `-32020`; another header → `400` `-32022` `{supported, requested}`.
- **Modern:** `_meta` needs `protocolVersion` and `clientCapabilities` (else `400` `-32602`); `MCP-Protocol-Version`, `Mcp-Method` and, for `tools/call`, `Mcp-Name` (base64 sentinel form accepted) must match the body, checked before the version (else `400` `-32020`). Methods: `server/discover` (`supportedVersions` `["2026-07-28","2025-11-25","2025-06-18"]`, `capabilities {tools: {listChanged: false}}`, `instructions`, `ttlMs` 3600000, `cacheScope` `private`), `tools/list` (same caching hints; one page), `tools/call`. Other methods, including `initialize` and `ping`, → `404` `-32601`. Results carry `resultType: "complete"` and `_meta["io.modelcontextprotocol/serverInfo"]`. Application errors (unknown tool, invalid params) use HTTP `200`.
- **Legacy:** `initialize` echoes a supported version (else answers 2025-11-25), no session ID; `ping`, `tools/list`, `tools/call`, `server/discover`; every JSON-RPC error in HTTP `200`.
- Limits: 120 requests a minute and 2 concurrent tool calls per grant; 30 failed presented tokens a minute per address; `429` with a JSON-RPC body and `Retry-After`.

## Tools

`list_journals`, `search_entries`, `read_entry`, read-only (`annotations {readOnlyHint: true, destructiveHint: false, idempotentHint: true, openWorldHint: false}`), with JSON Schema 2020-12 input and output schemas, returning `structuredContent` and its exact serialization as the first text item (`audience: ["assistant"]`); while the copy is incomplete a second text item says "Some shared entries aren’t available yet."; errors the model can fix are `isError: true` without `structuredContent`. Every result has `copy {asOf, complete}`. Journal names, titles and text are untrusted data; the `instructions` say so.

- `list_journals` → `{journals: [{id, name}], copy}`: the journals whose item is in the copy.
- `search_entries` (`query` ≤ 500 characters, `journal_id`, `from`, `through` inclusive ISO 8601 with whole or fractional seconds and `Z` or an offset, `offset` 0–100,000, `limit` 1–50, default 25) → `{entries, nextOffset?, copy}`: entries of journals in the copy, newest first with ties by ID, matching the query in titles and text ignoring case and diacritics, with excerpts ≤ 1,000 characters and `truncated`.
- `read_entry` (`entry_id`, `offset` 0–100,000,000, `max_characters` 1–50,000, default 20,000) → `{entry, copy}`: text counted in extended grapheme clusters, with `truncated` and `nextOffset`. An entry whose journal isn't in the copy is "Not found, or not shared with this client."
- Entry objects: `id`, `journalId`, `title`, `date` (ISO 8601 UTC, whole seconds), optional `archivedAt`, `text` (plain text, or the Markdown of entries kept as Markdown source; the data of `data:` URIs is replaced with `[data omitted]` by the publishing device), `truncated`, and for `read_entry` `nextOffset`.
- Devices publish only live, settled entries of live shared journals: conflicts, unsynchronized changes, Recently Deleted, templates, history and images are never in the copy.

## Authorization

- **Metadata:** protected resource metadata at `/.well-known/oauth-protected-resource/mcp` (`resource`, `authorization_servers`, `scopes_supported ["journals:read"]`, `bearer_methods_supported ["header"]`); authorization server metadata at `/.well-known/oauth-authorization-server` (`authorization_endpoint /oauth/authorize`, `token_endpoint /oauth/token`, `registration_endpoint /oauth/register`, `revocation_endpoint /oauth/revoke`, `response_types_supported ["code"]`, `grant_types_supported ["authorization_code","refresh_token"]`, `code_challenge_methods_supported ["S256"]`, `token_endpoint_auth_methods_supported ["none","client_secret_basic","client_secret_post"]`, `authorization_response_iss_parameter_supported: true`, `client_id_metadata_document_supported` unless `Journal:ClientMetadataDocuments=false`). CORS `*`, `Cache-Control: no-store`.
- **Clients:** client ID metadata documents (an `https` `client_id` fetched over HTTPS port 443 to a public address only, checked on the connected socket, no redirects, 5 s, ≤ 16 KiB, cached ≤ 24 h; `client_id` must equal the URL; a document the server couldn't connect to — a DNS failure, a refused connection or a connection timeout — is retried after 30 seconds and logged once as a sign the server has no internet access, while a blocked address or an invalid document is refused as invalid) and dynamic client registration (RFC 7591; public or confidential clients; unsupported redirect URIs dropped; 10 an hour per address, 100 an hour in all, 500 clients; unused registrations removed after 30 days). Redirect URIs: `https`, or loopback `http` matched ignoring the port.
- **Authorization request:** `response_type=code`, `client_id`, `redirect_uri`, `code_challenge` (S256), `resource` (optional; must be this MCP resource up to scheme/host case, default port and a trailing slash, else `invalid_target`), `scope` (only `journals:read` is issued), `state`. The page shows the client's name (without control or formatting characters, one line, at most 40 characters) and a **number** from 10 to 99, unique among waiting requests, and polls `/oauth/authorize/status?handle=…` (`waiting`, `approved`, `allowed`, `declined`, `replaced`, `expired`). It redirects with `code`, `state` and `iss` once the code is released, or with `error=access_denied`, `state` and `iss` when the request is declined: by the owner, by a wrong number, or by revoking the agent before it connected. A new request with the same `client_id` from the same client address replaces that client's waiting request (`replaced`, no redirect).
- **Approval** (device-authenticated): `GET /v1/agent-requests` → waiting requests, newest first, `[{id, clientName, clientId, identifiedAs?, redirectHost, redirectKind, requestedAt, expiresAt, reconnectCandidate?}]` (never the number; `reconnectCandidate` is an active grant of the same `client_id` without a live refresh token, most recently used first); `GET /v1/agent-requests/{id}` → the same for one request, which is then no longer evicted to make room; `POST /v1/agent-requests/{id}/approve {number, grantId, wrappedKey, grantSecret, metadata?, expiresAt?}` (a known `grantId` reconnects that grant and omits `metadata`; a wrong `number` declines the request, `409 agent_request_mismatch`); `POST /v1/agent-requests/{id}/ready {complete}` after the first copy (the server releases the code itself 15 seconds after approval); `POST /v1/agent-requests/{id}/decline`. A known `grantId` is reconnected only when it's active, has the request's `client_id` and has no live refresh token (else `409 agent_not_reconnectable`); its client name and return host become the request's. Requests live 10 minutes (5 more once approved), in memory only; at most 3 wait per client address (IPv6 /64) and 20 in all, and when full the oldest unopened request from the address with the most waiting requests is evicted. Numbers of kept, replaced and evicted requests aren't reused until those requests would have expired. Hosts are shown in their ASCII (punycode) form when internationalized. A redeemed code whose exchange failed leaves its pending grant to be deleted when the request expires. Status polling for a handle the server doesn't know counts against the caller's address; the page reports `approved` from approval until the code is released. An approved grant is **pending** until its code is redeemed, then **active**; a pending grant whose code is never redeemed is deleted with its copy, and deleting it (`DELETE /v1/agents/{id}`) declines the request. Reconnecting a grant revokes its earlier tokens only when the new code is redeemed.
- **Token endpoint** (`application/x-www-form-urlencoded`, `Cache-Control: no-store`): `authorization_code` (single-use code, valid 60 s from when the browser receives it; PKCE S256; `redirect_uri` if sent must match) and `refresh_token` (rotating; the previous token works 60 s more; later reuse revokes the family). Access tokens last 1 hour; refresh tokens 30 days unused; neither outlives the grant. **Revocation** (RFC 7009) revokes a token, and a refresh token its family.

## Keys and tokens

- Each grant has a copy key `K` (32 bytes) from the approving device. Subkeys: HKDF-SHA256(`K`, no salt, info `journal:v1:agent-copy:encryption` / `journal:v1:agent-copy:item-id`, 32 bytes).
- Approval sends `wrappedKey` = AES-256-GCM of `K` under HKDF-SHA256(`G₀`, info `journal:v1:agent-grant-wrap`, 32), AAD `journal:v1:agent-grant:{grant id}`, and `G₀` (32 bytes). The server keeps `G₀` in memory until the code is redeemed.
- Tokens: `mjat_` (access) or `mjrt_` (refresh) + base64url(token ID 16 ‖ verifier 32 ‖ secret `G` 32). The server stores the verifier's SHA-256 and `K` wrapped under that token's own `G` (same construction), deleted with the token; the copy key is unwrapped for one request at a time. Every connection uses `secure_delete`, and deleting wraps checkpoints the write-ahead log.
- Settings are sealed under the vault key with AAD `journal:v1:agent-metadata:{grant id}` (readable base64 JSON in unencrypted libraries). Version 2: `{version: 2, name, clientName, journals, expiresAt?, key}` where `journals` is `"all"` (every live journal, including ones created later) or an array of journal IDs; version 1 had `journalIds` instead and still opens. Devices keep chosen journal IDs they don't know.

## The copy

- Item ID: hex of HMAC-SHA256(`idKey`, `journal:v1:agent-item:{record UUID}`)[0..16]. Payload: AES-256-GCM under `encKey`, AAD `journal:v1:agent-copy:{grant id}:{item id}`, plaintext `{"kind":"journal","id","name"}` or `{"kind":"entry","id","journalId","title","date","archivedAt"?,"text"}`. Digest: hex of HMAC-SHA256(`idKey`, `journal:v1:agent-digest:` ‖ plaintext)[0..16].
- Version: the sync cursor the device applied, read in one transaction with the records used; the server keeps the highest and refuses lower or equal versions as stale.
- **Settings revisions.** Each grant has a `revision` (1 at approval). `PUT /v1/agents/{id} {revision, metadata, expiresAt?, removedItems?}` replaces the sealed settings and the end (a sooner end also shortens issued tokens) only from the current revision, and in the same transaction empties the listed items (payload removed, version 0, so sharing a journal again later publishes it whatever the cursor); it returns `{revision}`. Devices send the item IDs of the journals no longer shared and their entries, so an agent loses them at once: tools show only entries whose journal item is in the copy. A missing revision is `400`; an old one `409 agent_settings_changed`. Uploads name the revision their plan used, with the same rules, so a device with old settings can't upload a journal that was removed.
- Devices publish from synchronized state only: records with a pending change, a conflict or unreadable content are left as they are. Endpoints: `GET /v1/agents/` (`{id, state: pending|active|needsReconnect, clientName, clientId, redirectHost, createdAt, expiresAt, lastUsedAt, updatedAt, copyComplete, metadata, revision}`), `PUT /v1/agents/{id}`, `DELETE /v1/agents/{id}`, `GET /v1/agents/{id}/items` (manifest), `POST /v1/agents/{id}/items {revision, items: [{id, version, digest, payload|null}], complete?}` (a deletion's `payload` is `null` or absent) (≤ 200 items, 8 MiB; 20,000 items or 128 MiB per grant), `GET /v1/agents/{id}/activity` (newest 50 `{at, tool}`).
- 20 grants at most. Expired grants lose their tokens and copy at once and are removed after 30 days; a restored backup and turning on encryption remove every grant, token and client.
