# Container cases

Archives that exercise the ZIP layer of the file archive ([archive.md](../../../../archive.md)) and nothing else. `../container-v2.json` lists them. Every case gives the manifest the reader is handed (`manifest`, or `manifestText` where the text is the defect), the outcome (`accept`, `damaged` or `newer`) and a note naming the defect. `parseHeader` means the reader also checks the opaque-looking `archive.json` as a header up to the envelope bounds, without a password (a header's sealing and password are covered by `../encrypted.zip`).

A reader runs, for each case: find the end records and read the central directory, read `archive.json`, parse the manifest, check the listed entries and data ranges, and extract exactly the listed entries while hashing them. It passes the case when it accepts (and the extracted bytes match the manifest) or refuses in the stated class.

## How the cases are made

`make-container-cases.py` writes every `.zip` (except the `real-*` samples) and `../container-v2.json`. It is deterministic and is run with `python3 make-container-cases.py`. It assembles the bytes with `struct`, because most of the invalid archives are forgeries that no ZIP library will write, and it reads each accepted case back with Python's `zipfile` as a cross-check, so a case that is meant to be valid but that a mainstream library cannot read is caught when it is made.

## What they cover

- **Accepted:** stored and deflated entries; data descriptors (sizes only in the central directory); a local header with flag bit 3 and non-zero, wrong sizes; wrong local sizes without bit 3; a local ZIP64 extra field while the central sizes are not saturated; ZIP64 structures on a small file, and ZIP64 end records that the ordinary record agrees with; unknown extra fields and an archive comment; unlisted noise (`__MACOSX/._journal.sqlite`, `.DS_Store`, `notes.txt`, a folder entry, an unlisted UUID-named file once, an entry with an unknown flag and method); another entry order; no images; a zero-length stored entry and the empty deflate stream; local and central extra lengths that differ; names that look like profile names but are not; a deflated entry of about 6 times and of exactly 8 times expansion; unknown members in the manifest; a valid header.
- **Damaged, structure:** random bytes, an empty and a truncated file; a central directory offset or size out of range; an end record whose comment length does not reach the end of the file, or followed by trailing bytes; **two end records reaching the end of the file (a consistent forgery inside a comment)**; an entry count that is too small or too large; a non-zero disk number; ZIP64 and ordinary end records that disagree; a ZIP64 locator without a record; a saturated end record without ZIP64 records; sizes and offsets near 2^64; a saturated field without a ZIP64 value, or with too short a value; a central entry whose name, extra field or comment runs past the directory; a listed compressed size larger than the file; a duplicate `journal.sqlite`, `archive.json` or **unlisted** UUID-named name; a local header whose name, method or signature differs from the central directory's; a central offset that is not a local header; two listed entries whose data overlap, `archive.json` inside a listed entry, and a listed entry whose data reaches over the central directory.
- **Damaged, entries:** the encryption flag, the strong-encryption flag, method 12 and method 99 on a listed entry; the central-directory-encryption flag on any entry; a listed entry missing; a size that differs from the manifest or from the central directory; a stored entry whose compressed size is not its size; a deflate entry of compressed size 0; a stale CRC-32; a SHA-256 that differs; a deflate stream that would expand past its declared size (a small file, a large output: the reader stops at the declared size), that ends early, that has trailing bytes inside the compressed size, and that expands just over 8 times or far more; an `archive.json` declaring more than 16 MiB.
- **Damaged, manifest and header:** duplicate member names; a size that is a float, an exponent, negative, above 2^53 − 1 or has a leading zero; keys that are upper-case, in braces, without hyphens, a path or `../x`; a hash in upper-case hex; text that is not JSON; a repeated `recovery` member; iterations below and above the bounds; a salt of 15 bytes; recovery formats 3 and 4; no `archiveVersion`, version 1, `2.0`; a byte order mark; a trailing comma; a manifest that is not base64. `archiveVersion` 3 is `newer`.

## Real-tool samples

`real-*.zip` hold the same four entries (stand-in database, two images, opaque header) written by tools other than this repository's code, so the profile is proven against what other platforms produce. `make-real-tool-samples.py` writes them; they are committed once and are not rewritten by the container script. All are `accept` cases. The tools and versions that wrote the committed files:

| File | Tool |
| --- | --- |
| `real-dotnet-seekable.zip` | .NET SDK 10.0.401 (runtime 10.0.12), `System.IO.Compression.ZipArchive` in `Create` mode over a seekable stream, `CompressionLevel.NoCompression` (method 0), entry times 1980-01-01 |
| `real-dotnet-nonseekable.zip` | The same over a stream that cannot seek: flag bit 3, data descriptors |
| `real-python-zipfile.zip` | Python 3.13.5 `zipfile`, `ZIP_STORED`, times 1980-01-01 |
| `real-info-zip.zip` | Info-ZIP `zip` 3.0 (July 5th 2008, with modifications by Apple Inc.), default settings: deflated, extended timestamp and Unix owner extra fields |
| `real-ditto.zip` | macOS 26.3 `ditto -c -k --sequesterRsrc` (the engine behind Archive Utility), from files with an extended attribute: `__MACOSX/` folder and `._` entries, folder entries, data descriptors on deflated entries |
