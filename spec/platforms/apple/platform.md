# Apple conventions

The cross-cutting decisions every Apple page follows, so that a page for one screen or flow ([README](README.md)) links here instead of repeating them and records only what is specific to its screen. Section numbers match [Windows conventions](../windows/platform.md), so a porter can read the same section number on both platforms and see what each does.

Status: **written from the source; not yet verified against the running apps.** Every section below is written from the Swift source in `apps/apple` (the app, `Packages/JournalCore`, `project.yml`, the entitlements and Info.plist settings), the design records and the neutral spec, with the iPhone, iPad and Mac differences stated and a reason for each where the source gives one. Where the source gives none, or the behaviour is not in the source, the section says so ("not implemented", "not recorded", "not verified"). No section has been checked by running the apps. Repository paths are relative to the repository root; command placements are in [commands.md](commands.md), and what a command means in the spec's [commands.md](../../commands.md).

How to read a section:

- Product rules stay on every platform: data safety, quiet saving and syncing, plain copy, no exclamation marks, nothing silently discarded, nothing of the journals shown while locked.
- Each section covers iPhone, iPad and Mac. Where they differ, say so and why.
- Names in code font (`NavigationSplitView`, `NSTextView`) are SwiftUI, AppKit or UIKit types.
- Link the source files that implement the convention.

## 1 Target and toolkit

- **Toolkit.** SwiftUI for views and navigation, with AppKit on the Mac and UIKit on iPhone and iPad where SwiftUI has no equivalent: `NSSplitViewController`, `NSToolbar`, `NSPopover` and `NSTextView` on the Mac; `UITextView`, the keyboard accessory, popover presentation and `UIImagePickerController` on iOS. One source tree, `apps/apple/JournalApp`, with `#if os(macOS)` and `#if os(iOS)` branches. iPhone and iPad are one iOS target (`TARGETED_DEVICE_FAMILY` 1,2); the layout follows the size class, not the device (`UIDevice` is only used to name the device, "iPhone" or "iPad", in copy: `JournalApp/Model/DeviceAuthentication.swift`).
- **Minimum OS** (`apps/apple/project.yml`): iOS and iPadOS 16.0, macOS 14.0; the iOS UI-test bundle needs 16.4. `Packages/JournalCore/Package.swift` still declares macOS 13 and iOS 16. The Mac needs 14 for its AppKit window (`NSSplitViewItem.canCollapseFromWindowResize`, `NSHostingController.sceneBridgingOptions`, `NSPopover.show(relativeTo:)` on a toolbar item: [mac-window-appkit](../../../docs/design/mac-window-appkit.md), [performance](../../../docs/performance.md)). Why iOS 16 and not later is not recorded in the source; `docs/performance.md` notes it is the reason the shared model is an `ObservableObject` and not `@Observable`. Newer APIs sit behind `#available` (iOS 17: Search Entries presenting the field and the picture menu; iOS 26: bottom-bar search, glass reading bar, toolbar spacers; macOS 26: sidebar edge effect, the Recently Deleted header).
- **Targets and schemes.** `JournalMac` and `JournalIOS` are the apps (display name "My Journal", module name `Journal`); test bundles `JournalMacTests`, `JournalMacServerTests`, `JournalMacSandboxTests`, `JournalIOSTests`, `JournalIOSUITests`. Schemes: My Journal (Mac), My Journal (iOS), `JournalMacSandbox`, `JournalServerRecovery`. Three more opt-in projects, `file-acceptance.yml`, `measurement.yml` and `screenshots.yml`, sit beside `project.yml`.
- **Project generation.** The Xcode project is generated by XcodeGen from `project.yml` (`scripts/generate-apple.sh`) and is not committed; the Info.plist files are generated into `apps/apple/Generated/` (ignored by git). Edit `project.yml`, never the project. Xcode 26.6 ([docs/development.md](../../../docs/development.md)).
- **Language.** Swift 5.9 language mode with `SWIFT_STRICT_CONCURRENCY: complete`, warnings as errors. UI on the main actor (`AppModel`), persistence in an actor (`JournalStore`).
- **JournalCore** (`apps/apple/Packages/JournalCore`) is the non-UI package: document model, Markdown, encryption, store, sync, archives, agent copies, pairing. It imports no UI framework; it does use system frameworks (CryptoKit, Security, ImageIO, UniformTypeIdentifiers), which a port replaces. Views call `AppModel`; they never open the store ([apps/apple/AGENTS.md](../../../apps/apple/AGENTS.md), [docs/architecture.md](../../../docs/architecture.md)).
- **Third-party packages**: GRDB (SQLite access, `Store.swift`), swift-markdown 0.9.0 and its swift-cmark (reading and writing entry Markdown), both pinned in `Package.resolved`; notices in `JournalApp/Resources/ThirdPartyNotices.txt`. Cryptography is the system's: CryptoKit (AES-GCM, HKDF) and CommonCrypto PBKDF2 through the small C target `CJournalCrypto`. No analytics, no UI libraries, no HTTP library (`URLSession`).

## 2 App shell and window

- **Mac.** One window: `WindowGroup(id: "journal")` shows `RootView`, whose columns are AppKit's `NSSplitViewController` (`JournalSplitViewController`, three `NSSplitViewItem`s: sidebar, content list, plain detail), each hosting SwiftUI through `NSHostingController`, wrapped by `MacJournalWindow` (`JournalApp/Views/Mac/`). Reason: SwiftUI's three-column split view put toolbar sections at fixed positions and ignored `.detailOnly`; AppKit gives Notes' behaviour ([mac-window-appkit](../../../docs/design/mac-window-appkit.md)).
- **Mac sizes.** Window `.frame(minWidth: 801, minHeight: 420)`, `.defaultSize(width: 1100, height: 720)`. Sidebar 210 to 320 pt (230 preferred), list 360 to 460 (360 preferred), editor at least 439. A window too narrow for all three hides the sidebar first (`windowSizeProposed`); the list collapses only for Show Editor Only; the editor never. A column that returns widens the window if needed. Divider widths the person drags to are kept (saved 0.3 s after the drag).
- **iPad, regular width.** SwiftUI `NavigationSplitView` with three columns, `.navigationSplitViewStyle(.balanced)`: sidebar 180 / 220 / 320 pt (minimum, ideal, maximum), list 240 / 300 / 420. After choosing a collection the sidebar hides when the split view is narrower than 1,000 pt (`openRegularCollection`), so list and editor get the room.
- **Stacked navigation** (`RootView.usesStackedNavigation`): a `NavigationStack` over the path Journals, list, entry (`CompactJournalRoute`, `CompactJournalNavigation.swift`) when `horizontalSizeClass` is compact (every iPhone in portrait; iPad Slide Over, narrow Split View or Stage Manager windows) or when Dynamic Type is an accessibility size, on iPad too. The code reads the size class, so a device reporting regular width in landscape gets the split layout; not verified on a large iPhone.
- **Editor column.** At most 760 pt wide, centred, with a 24 pt side margin inside that width (`RootView.detailContent`). Nothing selected: "Select an Entry".
- **Toolbars by column.** Mac: sidebar (New Journal, sidebar button), list (collection title with entry count under it, Journal Actions), editor (New Entry, Formatting, Insert Image, Sync Status when needed, Editor Only, View Source, Entry Actions, search): see 4. iPhone and iPad: Journals screen (Settings top left on iPhone, New Journal, Edit), list (Journal Actions, Delete All in Recently Deleted; New Entry and search in the bottom bar), entry (Entry Actions, Done while writing); the reading bar below the text.
- **Restoration.** Mac: per window, `@SceneStorage("windowColumns")` (layout, the layout Editor Only replaced, sidebar and list widths: `WindowColumns.swift`); no app code stores the window frame. All devices: the open journal and entry are stored in `configuration.json` (`lastJournalID`, `lastEntryID`) and reopened after launch or unlock; stacked navigation opens straight on the entry (`revealsSelection`).
- **iPad multitasking.** `UIRequiresFullScreen` is not set and all four orientations are declared on iPad (three on iPhone), so Split View, Slide Over and Stage Manager resize the layout through the size class; a change to stacked rebuilds the path on the model's collection and entry (`RootViewAdaptations.swift`).

## 3 Windows and scenes

- **Mac: one journal window.** `NSWindow.allowsAutomaticWindowTabbing = false` and File ▸ New Window is removed (`CommandGroup(replacing: .newItem)`), so there are no tabs and no menu item opens a second journal window. Settings is its own window (`Settings` scene) and can be open with no journal window. `AppModel` is one object for the app (`@StateObject` in `JournalApp.swift`); closing the window does not quit, and a menu command that needs the window opens it again first (`inJournalWindow`).
- **Sheets that are windows.** The Mac's Add Device sheet asks the system to keep its window out of screen sharing and recordings (`AddDeviceView.swift`, `sharingType = .none`). Everything else is a sheet of the journal window.
- **Closing with unsaved writing (Mac).** `WindowCloseGuard` puts a proxy in front of SwiftUI's window delegate: closing saves first (`flush`); if saving fails, an `NSAlert` ("Keep Open") says the changes could not be saved and the window stays. Quit does the same through `applicationShouldTerminate` (`.terminateLater`), then sends writing to the server for at most 3 s. Unsynced items never block closing or quitting: they stay in the outbox on disk and go on the next sync (`WindowSafety.swift`, [flows/save-entry](../../flows/save-entry.md)).
- **iOS: one scene.** `project.yml` declares no scene manifest and no multiple-scene support, so the iPad app is not offered additional windows (not verified at run time). Lifecycle is `scenePhase` in `JournalApp.swift`: entering the background persists the last-synced time, locks (when App Lock is on) and saves inside a background task (`BackgroundActivity`); becoming active restarts sync at once.
- **State restoration.** There is no `NSUserActivity`, Handoff or state-restoration code. The open journal and entry come from `configuration.json` (see 2); writing is already saved, because every change starts a save to the device at once ([flows/save-entry](../../flows/save-entry.md)).

## 4 Menus and toolbars

- **Mac menu bar**: SwiftUI `Commands` (`JournalCommands`, `JournalApp/AppCommands.swift`). My Journal (system items plus Settings… from the `Settings` scene, and Lock My Journal above Services); File (New Entry, New Blank Entry, New Entry from Template…, New Journal…, Pin Entry; Import Archive…, Export Archive…, Export Journals as Markdown…; Delete All in Recently Deleted…; Close); Edit (`TextEditingCommands`, the system Find items, Search Entries); Format (`CommandMenu`, enabled only while writing); View (`SidebarCommands`, Show Editor Only, Previous and Next Entry, View Source, Zoom In, Zoom Out, Actual Size, Enter Full Screen); Window; Help (replaced by `HelpMenuItems`: guide, support, privacy policy, source code, Rate My Journal; there is no help book).
- **iPad.** The same `Commands` appear in the iPadOS menu bar and the ⌘-hold list, without the `#if os(macOS)` items (Delete All command, Editor Only group, Lock My Journal, Format ▸ Table). Search Entries needs iOS 17. `JournalAppDelegate.buildMenu` swaps the Find shortcuts after the system builds the menu (`FindKeyCommands.swift`). iPhone has no menu bar.
- **Mac toolbar.** AppKit's `NSToolbar`, built by `JournalToolbarController` from a `JournalToolbarConfiguration` that `RootView` rebuilds on every update (`RootView+MacWindow.swift`). Icon only, no customisation. Sections follow the split view's dividers with tracking separators, as in Notes. Items, leading to trailing: New Journal (`folder.badge.plus`), sidebar toggle, [list] flexible space, Journal Actions (`NSMenuToolbarItem`, `ellipsis`), [editor] New Entry (`square.and.pencil`), Formatting (button with an `NSPopover`, `textformat`), Insert Image (`photo`), Sync Status (`exclamationmark.icloud`, only when sync needs the person; its slot is reserved so nothing moves), Editor Only (`rectangle.center.inset.filled`), View Source or View Preview, Entry Actions (`ellipsis`), a search field (`NSSearchToolbarItem`). A column's items leave before it collapses and return after it expands, so none overflow. Reason for AppKit: [mac-window-appkit](../../../docs/design/mac-window-appkit.md).
- **iPhone and iPad toolbars**: SwiftUI `.toolbar` (`listToolbar`, `mainToolbar`, `compactToolbar` in `RootView+Toolbar.swift` and `CompactJournalNavigation.swift`), with `ToolbarItemGroup(placement: .bottomBar)` for New Entry and, from iOS 26, `DefaultToolbarItem(kind: .search)`. While reading, a capsule `ReadingBar` (iOS 26 `glassEffect`, otherwise `.bar`) holds Formatting, Insert Image and View Source; while writing, the keyboard accessory `WritingAccessory` holds the same controls.
- **Tooltips.** `iconHelp` gives every icon-only control a tooltip on the Mac and on iPad with a pointer.
- Where each command id appears, with shortcuts: [commands.md](commands.md#menu-bar); definitions: [commands.md](../../commands.md).

## 5 Context menus

- **One list, two renderers.** A menu is described once as a `[MenuAction]` (`JournalApp/Views/MenuActions.swift`) and shown as a SwiftUI menu (`MenuActionsView`, for `.contextMenu`) or as an `NSMenu` (Mac toolbar menus). The entry row's context menu and Entry Actions are the same list (`RootView.entryActionCatalog`); a journal row's context menu and Journal Actions are the same list (`JournalSidebarView.swift`). Destructive items use the destructive role; Delete Entry or Delete Template is last.
- **Entry rows** (all devices): `.contextMenu`: right-click or Control-click on the Mac, touch and hold on iPhone and iPad.
- **Journal rows**: `.contextMenu`; on the Mac also the sidebar's empty area (New Journal…) through `.contextMenu(forSelectionType:)`. In iOS edit mode the row's count gives way to a visible ⋯ (`ellipsis.circle`) that opens the same menu.
- **Mac editor.** The `NSTextView` menu, with Edit Link… and Remove Link inserted beside the system's link items (`JournalTextView.menu(for:)`, `LinkMenuMac.swift`); a right-click on a picture gives the picture menu (Cut, Copy, Paste, Share, Save Image As…, Image Descriptions…, Delete: `ImageActionsMac.swift`), also reachable from the keyboard; a table cell has Table ▸ (`InlineTableGridMac.swift`).
- **iOS editor.** From iOS 17 a touch and hold lifts the picture and shows its menu (Copy, Share…, Save to Photos, Image Descriptions…, Delete) through `UITextViewDelegate`'s menu configuration (`ImageActionsIOS.swift`); on iOS 16 the system menu stays and VoiceOver custom actions give the full set. Table cells use the edit menu.
- Beyond these, [commands.md](commands.md#toolbars-context-menus-and-swipes) lists every item.

## 6 Touch, swipe and pointer

- **Swipe actions** (`RootView.swift`, entry rows): leading edge Pin or Unpin (Restore in Recently Deleted when the item can be restored directly); trailing edge Delete (destructive; in Recently Deleted it is Delete Permanently, which removes the row first and then asks). A full swipe runs the first action. On the Mac the same modifiers answer a trackpad swipe ([commands.md](commands.md#toolbars-context-menus-and-swipes) lists the leading one). Without a gesture: the context menu, Entry Actions, and on the Mac Delete or ⌘⌫ in the focused list (`CommandDeleteKey.swift`).
- **Drag and drop.** Journals reorder with `.onMove`: a handle in iOS edit mode, touch and hold then drag otherwise, a plain drag on the Mac; VoiceOver gets Move Up and Move Down actions on iOS ([docs/design/journal-order.md](../../../docs/design/journal-order.md)). The source has no drag code for entry rows.
- **Text drag and drop (Mac).** `JournalTextView` accepts its own Markdown type, image files and image data, and other apps' text (read as the entry's blocks); a drag out of the app gives a copy only, a drag within the entry moves (`NativeTextView.swift`). iOS uses the system `UITextView` drag and drop; the source has no iOS drop code for images (not verified).
- **Taps.** A checkbox toggles on tap or click (`InlineTasks.swift`).
- **Pointer.** No custom cursors or hover effects except `.hoverEffect(.automatic)` on the empty entry's "use a template" link; tooltips on the Mac and iPad pointer.
- **Not implemented**: pull to refresh (sync is automatic), pinch to zoom (Zoom is a menu command, see 22), haptics other than a success tick when a pairing code is scanned.

## 7 Keyboard shortcuts

- **Departures from system conventions**, each from the source's comments:
  - Search Entries is ⌥⌘F and Find and Replace… is ⇧⌘F, swapped from the system's, as in Notes (owner decision 2026-09-27): `FindMenuShortcuts.swift` (Mac), `FindKeyCommands.swift` (iPad, where Search Entries starts at ⇧⌘F because a taken shortcut is dropped from the menu).
  - Zoom In shows ⌘+ and also answers ⌘= (`ZoomInShortcut`); Zoom Out ⌘-; Actual Size ⌘0.
  - ⇧⌘D Show Editor Only; ⌥⌘↑ and ⌥⌘↓ Previous and Next Entry (⌘↑ and ⌘↓ stay text navigation); ⌃⌘L Lock My Journal; ⇧⌘⌫ Delete All in Recently Deleted… (as Finder's Empty Trash…); ⌥⌘N New Journal; ⌥⌘U View Source; ⌘K adds or edits a link.
  - Format: ⇧⌘7 bulleted, ⇧⌘9 numbered, ⇧⌘L checklist, ⇧⌘U mark checked, ⌘' quote, ⌘[ and ⌘] indent, ⌥⌘0 to ⌥⌘6 paragraph and headings, ⌥⌘C inline code, ⇧⌘X strikethrough.
  - Pin Entry has no shortcut, as in Notes. Buttons that hand over the journals' key, merge journals or add a device use ⌘↩ instead of ↩ so they cannot be chosen before reading (`commands.md`).
- **Only on the Mac**: Show Editor Only, Previous and Next Entry, Lock My Journal, Delete All, Format ▸ Table, ⌘, for Settings (system), ⌃⌘S sidebar, ⌥⌘T toolbar, Window and Full Screen items. **iPad** needs a hardware keyboard for any of them; **iPhone** with a hardware keyboard reaches only the text view's own shortcuts (marked in commands.md).
- **Uniqueness.** No two menu-bar commands share a shortcut (`MenuShortcutTests`).
- **Text keys** (Return, Tab, Backspace, Down Arrow at the end of a code block): [flows/editing-rules](../../flows/editing-rules.md).
- Full list: [commands.md](commands.md#menu-bar).

## 8 Alerts and confirmations

- **SwiftUI `.alert`** is used for: the generic error (one per window; title "My Journal" in the source while the catalog's `common.alertTitle` reads "Journal", see [open-questions B5](../../open-questions.md); OK, plus Try Again while a save has failed); destructive confirmations whose title names the item (Delete “name”?, Delete Permanently, Delete All, Erase Journals and Settings?); a one-field name prompt (New Journal, Rename Journal, Save as Template: `TextField("Name")`, Cancel, a confirming button disabled while the trimmed name is empty); the name-taken notice; App Lock Is Off; Camera and Photos access notices (Open Settings).
- **`.confirmationDialog`** for choosing between outcomes: Stop syncing, revoke a device or an agent, keep one version of a conflict, discard description changes.
- **Destructive pattern.** The destructive button has `role: .destructive`; Cancel has `role: .cancel` (Escape on the Mac). Delete Entry has no alert: it moves to Recently Deleted at once and Undo brings it back. The alert is built after the state is checked (`prepare`), so it only offers what can happen; the Erase alert offers Export Archive… first when journals would be lost.
- **AppKit and UIKit alerts** only where SwiftUI cannot ask: `NSAlert` when a window close or quit cannot save (`WindowSafety.swift`), `UIAlertController` for Photos access from the picture menu.
- **Inline instead of alerts**: a failing save in the entry (`SaveFailureNotice`, Not Saved with Try Again), conflicts and recovery notices above the editor, and every sync problem (Sync Status menu, Settings ▸ Sync): sync never raises an alert.
- **One at a time.** SwiftUI drops an alert presented while another is dismissing, so a follow-up waits 350 ms (`afterAlertCloses`). Every alert and sheet closes when the app locks (`RootView.closePresentations`).

## 9 Sheets, popovers and notices

- **Sheets** (`.sheet`): flows with several fields or steps (Connect to a Server, Add Device, Move Entry, Merge, histories, Change Date, archive import, export, templates, Links, Turn On Encryption, password steps). iOS content is a `NavigationStack` with Cancel (`.cancellationAction`) and the confirming button (`.confirmationAction`) in the bar; the Mac gives each sheet a minimum size (440 by 300 for Connect to a Server) and puts its buttons in the sheet's toolbar or a bottom row (Change Date). Escape is Cancel and Return the default button; ⌘↩ where Return would be unsafe. `interactiveDismissDisabled` while an operation runs; Settings on iPhone and iPad is itself a sheet (10).
- **Popovers**: Formatting is an `NSPopover` on the Mac (transient, no animation, `ToolbarPopover` in `MacFormattingButton.swift`), a `UIPopover` on iPad in regular width and a panel in place of the keyboard on iPhone and in compact or accessibility sizes (`MobileFormattingPresenter.swift`). The template chooser is a popover in regular width and a sheet with medium and large detents otherwise (`TemplateSuggestionView.swift`); from File ▸ New Entry from Template… it is a sheet. Writing-time panels open and close without animation ([menus-and-popovers](../../../docs/design/menus-and-popovers.md)). A size-class change closes a popover rather than turning it into a sheet.
- **Menus** are native: `Menu`, `NSMenu`, `UIMenu`.
- **Notices** are inline bars above the writing, never over it: recovery, conflict and image-import notices (`.background(.quaternary)`), Not Saved below it on the Mac; at accessibility sizes a notice is capped at half the column and scrolls. The Mac's connection-paused notice sits at the top of the detail column.
- **Locking** closes every sheet, popover, prompt and file picker. **A second request while one is open**: the source has no general queue; a follow-up alert waits 350 ms for the previous one (`afterAlertCloses`), an archive opened from outside waits until the library is ready (`pendingArchive`), the generic error alert is not shown while locked or while the first journal is being created, and a sheet whose operation must not overlap checks its own state (`replacingVault`, `busy`).

## 10 Settings

- **Mac**: the `Settings` scene (`SettingsView` in a `TabView`): General, Sync, Devices, Privacy, Backup, Agent Access, each pane 560 pt wide and as tall as its content (`SettingsView.swift`). Opened with ⌘, or the system's Settings… item; opened from code by `SettingsPresenter` (`openSettings`). `AppModel.settingsTab` keeps the last tab for the process.
- **iPhone and iPad**: a sheet (`.sheet(isPresented: $model.settingsPresented)`) with a `NavigationStack`: a list of Writing, Sync, Devices, Privacy, Backup, Agent Access, then About and Erase sections, Done in the bar. Entry points: the gear at the top left of the Journals screen (iPhone, and iPad in stacked layout) or the last row of the sidebar (iPad).
- **Reasons for the differences**: a window with tabs is the Mac idiom (System Settings, Apple's apps) and can stay open beside the journal; iOS Settings are pushed pages in a modal. The first pane is Writing on iOS and General on the Mac because the Mac pane also holds Erase Journals and Settings…; About exists only on iOS because the Mac has the Help menu.
- **Opening a pane directly**: Sync Status ▸ Sync Settings… (`openSyncSettings`): sets `settingsTab = .sync` on the Mac and `settingsRequestedTab` on iOS, consumed once when the sheet appears; Show Progress for encryption sets Privacy (Mac). The Add Device, connect and conflict-review sheets belong to the Settings view.
- **While locked or when the library cannot open**: one line of text instead of panes.
- Detail: [screens/settings](../../screens/settings.md), [screens/settings-general](../../screens/settings-general.md).

## 11 Progress and announcements

- **Progress.** `ProgressView` with a label for operations the person waits on ("Opening Journal…", "Saving…", "Moving Entry…", "Restoring Version…"); a small spinner next to a button for short ones (`controlSize(.small)`); a determinate `ProgressView(value:)` for Turn On Encryption. Archive and Markdown export show their spinner only after 300 ms; Sync Now shows "Syncing…" for at least 0.5 s so it reads as done rather than as a flicker. Routine saving and syncing show nothing.
- **Announcements.** `JournalAccessibility.announce` posts a VoiceOver announcement (`UIAccessibility.post(.announcement)` on iOS, `NSAccessibility` `.announcementRequested` at medium priority on the Mac); `announceForAccessibility` is the same at high priority for status changes the person may not be looking at (pairing steps, encryption, agent access). Announced: Sync Now's result (Synced, Couldn't sync), Not Saved, errors in sheets, "Copied", "Pinned" or "Unpinned", "Image added", "Image deleted", "Saved to Photos", "Link removed", "Code found", a Markdown shortcut's conversion, a list level, "Merged into …", and wrong-password or mismatch messages.
- **Focus after an action**: `JournalAccessibility.screenChanged()` after unlocking or after Erase (600 ms later, once the sheet is gone); `@AccessibilityFocusState` returns VoiceOver to a row that came back and to the lock screen's button after a cancelled prompt.
- Per page: the page's Accessibility section.

## 12 Copy: casing, variants and vocabulary

- **Casing.** Title Case for titles, buttons, menu items and short labels ("Try Again", "Delete Journal…"); sentence case for full sentences, footers and Mac form labels (see variants). Actions that need more input end in "…"; typographic apostrophes and quotes (’ “ ”), no exclamation marks. The source has literal English strings, no `.strings` or `.xcstrings` catalogs, no localisation: counts are written in code ("1 entry" or "N entries").
- **Variants in [copy/en.json](../../copy/en.json)**: 20 keys have a `mac` text.
  - Sentence case in Mac forms (System Settings' convention): `settings.general.defaultJournal`, `settings.general.formatAsYouType`.
  - Pane name: `settings.pane.general` is "General" on the Mac (the tab also holds Erase), "Writing" elsewhere.
  - System prompt wording. The Mac prompt reads "My Journal is trying to …", so the reason begins in lower case there (`AppModel.authenticationReason`): `settings.privacy.appLock.reason.unlock`, `.turnOn`, `.turnOff`, `.change`, `settings.addDevice.authReason`, `settings.erase.authReason`, `settings.backup.markdownReason`, `settings.backup.markdownReasonUnencrypted`.
  - Vocabulary: a Mac user has a login password, not a device passcode: `library.lock.phrase.touchID`, `settings.privacy.appLock.noPasscode`, `settings.lock.turnedOff.passcodeRemoved`, `settings.lock.turnedOff.pinRetired`. The Local Network path is "System Settings > Privacy & Security > Local Network": `settings.connect.nearby.denied`.
  - Layout words: `library.moveEntry.renameExplanation` names the sidebar (Mac) or the Journals list (iOS); `library.templateChooser.journal` is "Journal:" beside a Mac pop-up; `library.recentlyDeleted.deleteAll` is "Delete All…" in the Mac bar (the catalog says "since it asks first"; the iOS button asks too and has no ellipsis); `library.journalHistory.confirm.restore` is "Restore Settings" on the Mac (no reason recorded).
- **Apple vocabulary that other platforms replace**: Face ID, Touch ID, Optic ID, "passcode", "login password", "this iPhone", "this iPad", "this Mac" (from `DeviceUnlockMethod`, `deviceName`), Settings versus System Settings, Photos, Files and iCloud.
- Neutral text: [spec/README.md](../../README.md) (Copy keys).

## 13 Device authentication and App Lock

- **API.** `LocalAuthentication`, policy `.deviceOwnerAuthentication`: Face ID, Touch ID or Optic ID with the device passcode (iPhone, iPad) or login password (Mac) as the fallback; on the Mac the system also offers a paired Apple Watch. A new `LAContext` per request; the app has no PIN of its own (`JournalApp/Model/DeviceAuthentication.swift`, [app-lock-system-auth](../../../docs/design/app-lock-system-auth.md)). Face ID needs `NSFaceIDUsageDescription` in the iOS Info.plist; the Mac needs no key.
- **Naming the method** (`DeviceUnlockMethod`): from `biometryType`, so a Touch ID that is only out of reach (lid closed) keeps its name; with no enrolled biometrics, or Face ID denied to the app, it is Passcode (iOS) or Login Password (Mac).
- **Unavailable.** No passcode or login password: App Lock cannot be turned on, and an App Lock that is on turns itself off at the next unlock with an alert (`AppLockTurnedOffAlert`). Other failures show "couldn’t be unlocked" and, when the library has a password, a link to the recovery credential (master password or recovery key), so the lock is never a dead end. Biometric enrolment changes are not tracked (anyone who knows the passcode can already enrol).
- **What App Lock is.** A gate on the interface, not a key: the vault key is a Keychain item that App Lock never touches (see 14).
- **When it locks** (`AppLockOperations.swift`): at launch; iPhone and iPad as the app enters the background (`applicationEnteredBackground`, `prompting: true`); Mac on Lock My Journal (⌃⌘L, Settings ▸ Privacy), when the screen locks (`com.apple.screenIsLocked`), on sleep, when another user takes over, and after inactivity (`InactivityLock.swift`: 5, 15, 30 or 60 minutes or Never, 30 by default, Mac only; lengthening it or choosing Never asks for authentication first). Saving always comes first (`saveBeforeLocking`). On the Mac an action in progress (connecting, importing, adding a device) holds the inactivity timer (`keepsUnlockedWhile`).
- **While locked** (`UnlockView.swift`): a lock symbol, "My Journal Is Locked" (a heading) and one prominent button "Unlock with {method}" (the default action, so Return on the Mac). iPhone and iPad ask the system without a tap once the app is active; the Mac asks at launch and otherwise waits for the button. Nothing of the journals is built; on the Mac the toolbar and window title are cleared (`JournalToolbarController.uninstall`).
- Flow: [flows/app-lock](../../flows/app-lock.md), [screens/lock-screen](../../screens/lock-screen.md).

## 14 Secure storage

- **What is stored**: the vault key and the sync connection (server address, device token), as generic passwords of service `org.privatejournal.vault` (`Packages/JournalCore/Sources/JournalCore/Keychain.swift`), accessible `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, never synchronised through iCloud Keychain; `configuration.json` names the accounts (`keyID`, `connectionKeyID`).
- **Which keychain.** Every query names it with `kSecUseDataProtectionKeychain`. iOS uses the data protection keychain (the iOS target has no entitlements file and the code names no access group, so the default group applies). The Mac uses it when the build carries the keychain access group `$(AppIdentifierPrefix)org.privatejournal.vault` (`Signing/JournalMac-Development.entitlements`, used by team-signed and App Store builds: [mac-app-store-sandbox](../../../docs/design/mac-app-store-sandbox.md)); a build without it (`Signing/JournalMac.entitlements`, CI) gets `errSecMissingEntitlement` on the first change and uses the login keychain for the rest of the process.
- **Migration.** `MigratingSecretStore`: an entitled Mac build that finds a key only in the login keychain copies it, reads the copy back, then removes the original; any failure leaves the original and returns the key. Login keychain items can only be deleted by the build that made them, so a copy may stay but is never read again ([docs/architecture.md](../../../docs/architecture.md), Data on a device).
- **When an item cannot be read.** A missing vault key with a password library: the lock screen with the credential field (`needsKey`) and Import or Erase; a library without a password quietly gets a new device key. A keychain error while opening: the library-problem screen with Try Again, Import Archive and Erase (`LibraryProblem.swift`). On iPhone and iPad, before first unlock the files and keys are unreadable, so a failed open ends by itself and offers nothing destructive (`protectedDataAvailable`).
- **Because the items are this-device-only**, restoring an iPhone or Mac from a backup brings the library without its key; the person unlocks with the recovery credential.
- **Tests** use an in-memory store (`XCTestCase` detection), never the person's keychain. Erase lists only the data protection keychain by account name.

## 15 Pasteboard

- **Written by the editor.** Copy and Cut give the entry's own Markdown (`org.myjournal.markdown`, so images, tables and lists survive a paste into another entry), formatted text with lists written as text for other apps (RTF), and plain text (a table's Markdown when a table is selected). A selected picture is written as the image in its original format plus the entry's Markdown, and no text, so other apps take the picture.
- **Accepted.** The entry's own type first; images (`PastedImages.swift`: HEIC, HEIF, JPEG, PNG and GIF kept as the file's bytes, TIFF and bare images encoded once to JPEG at 0.9 or PNG when transparent; image files; never an image that is only the picture of copied text); formatted text from other apps becomes the entry's blocks (headings, lists, quotes, code, links) with fonts, colours and sizes dropped and nothing a web page refers to loaded (`PastedRichText.swift`, [pasted-text](../../../docs/design/pasted-text.md)); plain text one paragraph per line. Paste and Match Style pastes plain text.
- **Secrets.** Only the recovery key goes through `SensitivePasteboard`: local only (not shared by Universal Clipboard), concealed from clipboard managers on the Mac (`org.nspasteboard.ConcealedType`), removed after 120 s, and on the Mac also when My Journal quits or locks. Other copy buttons (server address, pairing code, MCP address, image text) use the plain pasteboard; they copy short-lived codes or addresses, never a key.

## 16 Files, pickers and document types

- **Document type.** `org.privatejournal.archive`, extension `journalarchive`, a directory package (`com.apple.package`), exported by the app and declared as Viewer with handler rank Owner in both Info.plists (`UTExportedTypeDeclarations`, `CFBundleDocumentTypes`); iOS adds `LSSupportsOpeningDocumentsInPlace`. No URL scheme is registered. Format: [protocol/archive.md](../../../protocol/archive.md).
- **Export.** SwiftUI `.fileExporter` with a `FileDocument` (`JournalFile`): Archive as `.journalarchive` named "Journal Archive yyyy-MM-dd" (date in a fixed format), Markdown as a folder (`contentType: .folder`), recovery key as text ("Journal Recovery Key.txt"). Staged copies live in the data folder or temporary folder and are removed after the dialog and at the next launch (`ArchiveExportLeftovers`); the Markdown folder is excluded from backups and files are written with complete protection. Where: File ▸ Export Archive…/Export Journals as Markdown… open sheets (Mac, iPad); Settings ▸ Backup on every device.
- **Import.** `.fileImporter(allowedContentTypes: [.journalArchive])` from Settings ▸ Backup, the welcome screen, the lock screen of a missing key, and File ▸ Import Archive…. The picked URL is read inside `startAccessingSecurityScopedResource`.
- **Opening from outside.** `.onOpenURL` in `RootView`: a file URL ending in `.journalarchive` is held (`pendingArchive`) until the library is open, unlocked and not busy, then `ArchiveImportView` opens as a sheet; it is dropped if the app goes to the background first. What a Finder double-click does on the Mac with no window open is not verified.
- **Images.** The Mac Insert Image uses an open panel (`.fileImporter`, images, several allowed); iOS Choose File… uses the same importer; Photos are in 26. The Mac sandbox grants `com.apple.security.files.user-selected.read-write` for these panels only.
- **Drag of files**: Mac only, image files into the entry (6).

## 17 App data, backups and erasing

- **Where.** One library per device under Application Support, folder `PrivateJournal`: `journal.sqlite`, `attachments/`, `configuration.json` ([docs/architecture.md](../../../docs/architecture.md), Data on a device). iOS: the app container. Mac: the App Sandbox container, `~/Library/Containers/<bundle identifier>/Data/Library/Application Support/PrivateJournal`; `MacResources/container-migration.plist` moves a library from the old unsandboxed folder when the container is created. `JOURNAL_DATA_DIR` selects another folder (inside the container on the Mac), for development and tests.
- **Mac sandbox** (every build): `com.apple.security.app-sandbox`, `network.client`, `files.user-selected.read-write`, plus the application-groups entitlement (see 18). No `network.server`: the app accepts no incoming connections (removed in build 19 after App Review flagged it).
- **System backups.** The code excludes only the temporary Markdown export folder from backups (`isExcludedFromBackup`); the library is left to the system's backup of the app container and sets no file protection class of its own. Its key is this-device-only (14), so a restored backup needs the recovery credential.
- **Other state**: `UserDefaults` holds the Markdown-as-you-type switch (`formatMarkdownAsYouType`), the last-synced time per library and the rating usage; the Mac's `@SceneStorage` holds the columns. Nothing is in iCloud (no CloudKit or key-value store).
- **Erase Journals and Settings** (`EraseOperations.swift`, `LocalErasure.swift`, [flows/erase](../../flows/erase.md)): warns by sync state and asks for the device's authentication when App Lock is on; commits by moving `configuration.json` into an `erased-<UUID>` folder, then removes the library folders, Keychain accounts by exact name (plus a sweep of the app's own service), temporary export copies, preferences it owns and the rating usage; an interrupted erase is finished at the next launch (three attempts for stubborn Keychain items). It never removes files of the former Mac server (`FormerMacServer.swift`), and never changes the server or other devices.

## 18 Packaging, distribution and updates

- **Targets and signing** (`apps/apple/project.yml`): bundle identifier fixed and shared by iPhone, iPad and Mac for one universal purchase; Mac hardened runtime on; automatic signing style, with team and identity passed by script, never committed (`scripts/build-mac-development.sh`; [apps/apple/AGENTS.md](../../../apps/apple/AGENTS.md)). `ITSAppUsesNonExemptEncryption` is false; a privacy manifest (`JournalApp/Resources/PrivacyInfo.xcprivacy`) declares no tracking and no collected data, and reasons for UserDefaults (CA92.1), file timestamps (C617.1) and disk space (E174.1, 85F4.1).
- **Entitlements, Mac** (`Signing/JournalMac.entitlements`; the development and App Store variant adds the keychain group): `com.apple.security.app-sandbox` (Mac App Store requires it); `network.client` (sync, discovery); `files.user-selected.read-write` (open and save panels); `com.apple.security.application-groups` (`$(TeamIdentifierPrefix)` plus the bundle identifier; today used only to find and clean agent files an earlier version left, `LocalAgentCleanup.swift`); the keychain access group (14). **iOS** declares no entitlements file; permissions are Info.plist usage strings (13, 16, 26, 32).
- **Distribution.** TestFlight and the App Store only, for iOS and for the Mac App Store; the Mac has no Developer ID or disk image channel ([mac-app-store-sandbox](../../../docs/design/mac-app-store-sandbox.md), [docs/release-operations.md](../../../docs/release-operations.md)). The build number comes from the workflow; `project.yml` keeps 1 locally. Mac category: Lifestyle.
- **Updates.** The app never updates itself and never checks for a new version; the App Store delivers updates. "Update My Journal" in messages is shown when a server or file needs a newer app.
- **Icon.** See 23. **Help and legal links** open the repository's pages (`AboutLinks.swift`); there is no help book.

## 19 Launching and activation

- **Cold launch.** iOS shows the system's blank launch screen (`UILaunchScreen: {}`); then `RootView` shows `ProgressView("Opening Journal…")` (copy key `library.app.loading`) until `AppModel.load()` has read the configuration and opened the library. Next: first-launch Welcome (no library), the lock screen (App Lock on), the library-problem screen, the recovery key screen, or the three-column or stacked library on the remembered journal and entry. The test host never opens a real library.
- **Launch work** (in order): finish an interrupted erase, read settings, move an old App Lock PIN to the device's authentication, remove abandoned copies, open the store and the saved connection, then lock or read the journals; then `noteLaunch` for the rating, removal of export leftovers, and on the Mac the inactivity lock and agent-file cleanup.
- **From a file.** An archive opened from Files or Finder reaches the import sheet as in 16. **Not implemented**: URL schemes, universal links, Handoff, Spotlight, App Intents, Shortcuts, widgets, quick actions.
- **Activation.** Becoming active restarts the sync loop and syncs at once (3 s pace while active); locked apps ask for authentication as in 13. A Mac command from the menu with no window open reopens the journal window first.
- **State restoration**: see 2 and 3.

## 20 Screen capture and app-switcher privacy

- **App-switcher cover.** With App Lock on, `PrivacyCover` (iOS) covers every window, including sheets, popovers and alerts, with a plain background (the label "My Journal Is Locked" only when actually locked) whenever the scene deactivates or enters the background, and removes it when the scene is active again. While the system's own authentication prompt is showing, the cover is not shown, or the prompt would be hidden. The Mac's equivalent is the `LockedCover` overlay in `JournalApp.swift`, shown while the app is not active and App Lock is on.
- **Without App Lock** nothing is covered: the app switcher shows the screen as it is. Not implemented: a cover for screen recording or mirroring (`UIScreen.isCaptured`), and a hidden-content setting.
- **Add Device codes.** The QR code (29) is hidden whenever the iOS app is not active, since the snapshot shows the inactive state, and on the Mac while the app is in the background; the Mac sheet's window is excluded from screen sharing and recordings (`sharingType = .none`).
- **Titles.** Locking removes the journal's title and subtitle from the Mac window and the Window menu.
- **Removed** when the scene becomes active again; if the app is locked, the lock screen is then what shows.

## 22 Typography

- **System fonts only** (SF; monospaced system font for code). Text styles: `.largeTitle` (Welcome), `.title2` (lock and result screens), `.headline` (step titles), `.body.weight(.medium)` (entry title in a row), `.callout` (preview, notes), `.caption` (row dates).

## 25 Text input and spelling

- **System preferences are respected, not overridden.** The Mac text view and the iOS text view set no spelling, correction, smart quote, smart dash, text replacement or autocapitalisation options of their own (`Editor/NativeEditor.swift`); table cells copy the entry view's settings (`NativeTableIntegration.swift`). The Mac find bar is the system's (`usesFindBar`); iOS uses the find navigator (`isFindInteractionEnabled`). The only overrides: the template search field turns autocorrection and autocapitalisation off, and password fields declare `.password` or `.newPassword` content types for the system's autofill (`PasswordAutofill.swift`).
- **Markdown as you type** is the app's own: a line-start marker converts when the space is typed (`- `, `* `, `+ `, `[ ] `, `[x] `, `> `, one to six `#`, `1.` or `1)`), "```" or `---` with Return makes a code block or a rule; each conversion is one undo step and Backspace right after puts back exactly what was typed. Settings ▸ Writing switches it off (`UserDefaults` key `formatMarkdownAsYouType`, on by default). Rules: [flows/markdown-as-you-type](../../flows/markdown-as-you-type.md), [flows/editing-rules](../../flows/editing-rules.md).
- **Input methods.** Text being composed (a marked range) is never replaced: external changes and conversions wait until the composition ends (`compositionEnded`, `pendingExternal`); the template chooser's Escape ignores a keystroke that belongs to a composition.
- **Pasted text** goes through the app's reader (15), not the system's, so nothing a page refers to loads.
- **iOS system formatting** is hidden in favour of the app's own formatting controls (`WritingAccessory.hideSystemFormatting`); Writing Tools and other system text features are not configured by the app (default behaviour, not verified).

## 28 Rating

- **Request.** `@Environment(\.requestReview)` from StoreKit, given to the window by `ReviewRequestPresenter`; the app has no prompt of its own. ## 29 QR codes and Add Device

- **Showing.** `PairingCodeImage` draws the invitation text with Core Image's QR generator, correction level M, black on white, a fixed 220 pt square with 16 pt padding and a rounded white background (so it scans in Dark Mode and does not grow with text size); VoiceOver gets one image labelled "Code for adding a new device". The text is `MYJOURNAL1.` plus URL-safe Base64 of handle, approver key, secret and server address (`PairingInvite.swift`); it has no colon so no app can register it as a URL scheme. Shown on every device that is connected and can approve; hidden while the app is inactive (20), and iPhone and iPad keep the screen awake while it shows (`isIdleTimerDisabled`); the code expires and "Show New Code" replaces it.
- **Scanning.** iPhone and iPad only: `DataScannerViewController` from VisionKit, QR codes only, one at a time, balanced quality, system guidance and highlighting, in a full-screen cover with Cancel and a caption; offered only where `DataScannerViewController.isSupported` is true (so not on simulators). A success plays a haptic and announces "Code found". Other QR codes are ignored; a newer code asks for an update.
- **Camera permission.** Asked when the scanner first appears (`AVCaptureDevice.requestAccess`); denied or restricted shows "Allow camera access in Settings to scan the code." with Open Settings.
- **Where scanning is unavailable (the Mac, devices without a scanner).** Connect to a Server has no Scan Code button; the new device chooses Add This Device, shows a nine-digit code (grouped "123 456 789", Copy Code), and the connected device types it in the Add Device sheet's code field (Continue) and compares the six-digit check code (Approve, then Connect). The same path works between any two devices. The Mac can show and approve, but not scan.
- Flows: [flows/pair-device](../../flows/pair-device.md), [screens/add-device](../../screens/add-device.md), [screens/scan-code](../../screens/scan-code.md).

## 30 Sync, lifecycle and background

- **Schedule** (`Model/SyncSchedule.swift`, [docs/architecture.md](../../../docs/architecture.md), Sync): while the app is open, unlocked and active, a pass every 3 s; every 30 s while another app is active (a Mac window behind others, iPad multitasking); becoming active syncs at once; after a failure the wait doubles up to 5 minutes; a success, Sync Now, unlocking or the network returning (`NWPathMonitor`) resets it. After a pass that settled, the change watcher can hold a request open for the server's changes (up to 20 s) instead of polling every 3 s (`ChangeWatcher`). Sleep and wake are reported to the change watcher (Mac).
- **Writing.** Every change is saved to the device at once; an entry being written is sent to the server after 2 s of quiet or 30 s of continuous writing, and at once when the entry is left, the app locks or goes to the background, or it quits (`sendWriting`).
- **Becoming inactive.** Nothing special. **Background (iOS)**: the last-synced time is stored; the app locks and saves, sends writing, inside `beginBackgroundTask` ("Save and lock", `BackgroundActivity.swift`); Turn On Encryption and the first agent-copy upload hold the same kind of task. Automatic sync pauses in the background.
- **Not implemented**: background fetch, `BGTaskScheduler`, push notifications or silent pushes. Nothing syncs while the iOS app is suspended; the next launch or activation catches up.
- **Mac**: the app keeps running with the window closed and keeps syncing at the 30 s pace; Quit and window close save and flush first (3).
- **iPad**: as iPhone when the scene is backgrounded; at the inactive pace in a neighbouring Split View or Stage Manager window.
- Behaviour: [flows/sync-recovery](../../flows/sync-recovery.md), [flows/save-entry](../../flows/save-entry.md).

## 31 Dates and formats

- **Storage.** An entry's date is an instant, written as ISO 8601 UTC to the second (`2026-09-20T12:00:00Z`); lists sort by it and group by month in the viewer's calendar ([protocol/records.md](../../../protocol/records.md)). Change Date edits the day with a system `DatePicker` (`displayedComponents: [.date]`); the source does not normalise the time of day.
- **Shown.** The user's locale, calendar and time zone, always through the system's formatters: month headers "LLLL yyyy" (`autoupdatingCurrent`); row dates `.dateTime.day().month(.abbreviated)`; histories and conflicts `.formatted(date: .abbreviated, time: .standard)` or `.dateTime`; devices and agents `.relative(presentation: .named)` and abbreviated dates; Last Synced as "Just now", a relative phrase within a day, "Yesterday at {time}", or "{day and month} at {time}" with the year added when it differs (`SyncActivity.description(of:)`).
- **Numbers.** Counts use `count.formatted()` (locale grouping) in text such as "9 entries" and badge counts; sizes use `ByteCountFormatter` (`.file`); pairing and setup codes are grouped by `CodeEntry` ("123 456 789").
- **File names** use fixed `yyyy-MM-dd` in the POSIX locale ("Journal Archive 2026-09-27.journalarchive") so they sort the same everywhere.
- **Writing days** for the rating are local calendar days.
- Text is English only; plurals are written in code.

## 32 Local network and servers

- **Addresses accepted** (`ServerClient.init`): a URL with a host and no user, password, query or fragment, and `https`, or `http` only for the loopback hosts `localhost`, `127.0.0.1` and `[::1]`. The address must be typed with its scheme (the field's prompt is an `https://` example); no HTTPS upgrade is attempted. Redirects are refused; sessions are ephemeral without a cache; ordinary requests time out after 20 s, the change wait after 30 s, image transfers after 15 minutes.
- **Plain HTTP is for development.** `PairingInvite.origin` accepts loopback HTTP only in debug builds, so a pairing code for such a server is refused in release builds, and Add Device then says other devices cannot connect (`AddDeviceView.swift`). The Mac's former built-in server address `http://127.0.0.1:46371` is recognised once to stop syncing with it (`FormerMacServer.swift`).
- **ATS.** No `NSAppTransportSecurity` exception is declared in `project.yml`; the loopback rule is the app's own check, not an ATS setting. Certificate failures are classified (`SyncHealth`) and worded plainly: "Can’t connect securely to the server because its certificate isn’t valid." (`NetworkFailureMessage.swift`).
- **Discovery.** `ServerBrowser` runs an `NWBrowser` for the Bonjour service `_myjournal._tcp` only while Connect to a Server is choosing a server; each result needs TXT `v=1` and an HTTPS `url`, and is only a suggestion checked like a typed address. Info.plist: `NSBonjourServices` `_myjournal._tcp` and `NSLocalNetworkUsageDescription` "Find and sync with your server on your local network." on both platforms.
- **Permission.** The first browse shows the system's Local Network prompt (iOS and macOS); a denial (`kDNSServiceErr_PolicyDenied`) shows `settings.connect.nearby.denied` (Settings on iOS, System Settings ▸ Privacy & Security ▸ Local Network on the Mac). Connecting to an address typed by hand does not use the browser; whether iOS asks for Local Network access when a typed address is on the local network is not covered by the source.
- **Sandbox.** The Mac sandbox needs `com.apple.security.network.client` for all of this.
- Flow: [flows/connect-to-server](../../flows/connect-to-server.md), [screens/connect-to-server](../../screens/connect-to-server.md).
